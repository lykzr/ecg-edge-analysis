## 接下来怎样接入

### 1. 补齐可执行的模型输入流水线

- [x] 取得模型负责人交付的完整输入实现及依赖/黄金样例ZIP；已做只读源码、清单与合成特征检查，尚未导入本项目或运行完整流水线。不能用任意192个采样值代替特征。
- [ ] 逐列核对`feature_names.json`的顺序、导联、幅值、采样率、滤波、归一化、历史背景和无效值规则。
- [ ] 核对后继RR何时可用，并把等待计入端到端延迟；断流或最后一拍没有后继时明确无效，不用未来未知值或专家标注补齐。
- [ ] 明确最终选型和重拟合/部署方式。三个外折模型不默认取第一折、平均或投票；192维v92与207/208维新版本不能混配。

### 2. 新建独立模型适配接口

- [ ] 保留现有`ECG-CLASS-1`及其128点+RR3、N/S/V/F合同，不能静默改成HGB输入或三类标签。
- [ ] 为HGB另定义有版本的输入/结果合同：模型/特征身份、session、beat_id、源样本位置、特征可用时刻、状态及N/S/VF类别表。
- [ ] 明确VF是V/E/F合并，不是心室颤动；不伪造独立V/F结果。训练方向和类别变化不得自动替代原CNN/INT8/FPGA目标。
- [ ] 首阶段在电脑侧验证适配器，显式记录执行位置及`accepted=false`；不将其结果冒称板端分类。

### 3. 与当前系统作同输入对照

- [ ] 从500Hz板端自动事件和对应源波形构造模型要求的输入，不假定当前默认发布已经传出全部特征或窗口。
- [ ] 直接研究推理与适配调用逐值比较；验证缺口、短窗、首RR、后继RR不足、重复、乱序、超时及会话重置。
- [ ] 原事件与分类结果按会话及心拍编号关联。现ECG-UART-1拒绝同号E重发，晚到分类如需回填必须另立协议，不覆盖原事件。
- [ ] 用同一开发输入复核端到端指标；160行合成特征只验证数值，不代替准确率。六名封存患者不用于此次对接排错。

### 4. 后续网页集成与部署

- [ ] 在系统/模型接口稳定后引入网页后台；采集与Zynq端口由唯一后台管理，保留Tk为诊断工具。
- [ ] OpenECG整段节律分析与HGB逐拍分类分别保存任务类型、模型身份和标签，不互相改名。
- [ ] 实际分类质量、真实无线、ARM/FPGA数值、资源及性能分别验收。没有合格交付前保留当前release，不把研究权重写入Flash。

## 当前阻碍

最初分支仅提供参数、特征名称和数值检查。2026-11-01已收到ecg-model-integration-20261031.zip及检查说明，补齐整段500Hz单导联mV到192维特征与HGB结果的源码；51项清单哈希、13个Python语法、三份权重/特征顺序与160组合成特征概率只读复核通过。新ZIP尚未导入本工程，其完整运行不能继承附件结果为本机实测。
