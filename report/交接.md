# 工程交接

本文件按用户要求命名为“交接.md”，是正式英文命名规则的一次明确例外。目标是让接手者从本Git提交直接开始工作，不靠原电脑的聊天或历史tmp。当前范围和未完成项以本页与对应专题计划为准，旧实验记录保留原语境。

## 先看当前事实

- 实物路线：ADS1292R→STM32→JDY18→USB接收器→电脑→USB_UART→Zynq→电脑。四段协议分别处理；电脑目前负责量化前去直流/标称转换、保存/中转/显示，QRS和切拍在ARM，最终CNN在FPGA的目标未取消。
- 新500Hz ARM应用构建ID：a570b308ef7b46fe。QRS/切拍/窗口/RR、数字USB双向通信、厂商CSV与模拟34字节源均有实板证据；分类后端仍为NO_MODEL，不输出有效N/S/V/F类别。
- 当前Flash镜像已写入并校验，用户彻底拔线掉电后BOOT_MODE=1，收到500Hz启动H；随后10412点CSV全部收发、26事件与同源C一致，无JTAG下载。QSPI复位后重新就绪亦通过。没有真实无线或检测准确率结论。
- QRS已知42条500Hz开发回归配对等效，原门槛仍41/42、105噪声误检风险未关闭。数据都已参与开发，不叫独立测试；不擅自恢复调参或读模型独立6人。
- 根README按用户要求保持原样；本页、docs/README.md、docs/download_guide.md是当前交接/操作入口。

## 接手后先运行

1. 获取含本文件的提交。此次只授权本地提交，尚未推送；只从旧origin克隆不会自动拿到本轮代码，项目所有者需自行推送本次提交后再通知队友。不要将未推送误称已共享。
2. Windows选择无中文/空格的短路径，例如C:/work/ecg_edge。PC标准库功能需要带Tkinter的Python；完整软件测试本机用Python3.14，另需已有GCC。Linux可检查部分核心，但Windows串口、PowerShell和Tk实物验收不能冒充跨平台通过。
3. 先做不连接板卡的完整性检查：

```powershell
python -B sim/check_checkout.py
python -B sim/check_system_release.py
```

4. 打开客户端：`python -B src/ui/main.py`。查看演示/日志不需要板卡；真实COM号按USB身份选择，不照搬本机COM14，不同时让Vitis/其他终端占用USB_UART。
5. 已写本版Flash的板卡：BOOT_CFG为1=ON、2=OFF，按实物ON丝印核对，彻底断电再上电；每轮结束后按PS复位键重新启动应用，不必重新擦写Flash。另一块板尚未写本版时先按下载教程核对型号/修订，再使用JTAG或明确执行QSPI编程。
6. 一次性临时JTAG仍可双击releases/latest/runtime500/download.cmd，先验SHA再核唯一Zynq。程序掉电后仍由当前Flash镜像启动，不能混称JTAG修改已固化。

## 完整离线测试与从零构建

不把本机环境或数据缓存提交到Git。接手者在自己的授权环境安装依赖，不自动运行下载盘安装器；安装命令仅供接手者执行：

```powershell
py -3.14 -m venv tmp/system_env
./tmp/system_env/Scripts/python.exe -m pip install -r data/requirements_system.txt
$env:ECG_HOST_CC = '<已有GCC的gcc.exe完整路径>'
./tmp/system_env/Scripts/python.exe -B sim/check_system_offline.py --output tmp/offline_new --clean-copy
./tmp/system_env/Scripts/python.exe -B -m unittest discover -s sim -p test_system_release.py
./tmp/system_env/Scripts/python.exe -B -m unittest discover -s sim -p test_qspi_release.py
```

新建输出目录；不要对整个sim盲目通配执行：部分测试需要Torch、Vivado或实际板卡，完整系统离线入口已选择依赖范围。Tk隐藏窗口通过不是人工视觉。GCC支持ECG_HOST_CC变量或PATH，无GCC时不要将编译依赖缺失当算法失败。

板级从零构建（使用接手者已装工具，不依赖本机Vitis工作区）：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File board/rebuild_system.ps1 -Output tmp/rebuild_new -VivadoBin '<Vivado>/bin' -VitisBin '<Vitis>/bin' -Python '<系统测试环境/python.exe>' -Rate 500 -Trace 0
```

运行中不搬工具工程。bit/XSA/init/FSBL/ELF必须来自同一清单；PS7/MIO/DDR不能套其他板卡预设。正常运行Trace=0；窗口逐值验收另构建Trace=1，不拿调试输出做持续带宽结论。

仅重建已经发布的启动镜像，无需作者tmp或重新生成ELF：

```powershell
python -B board/prepare_qspi.py --release releases/latest --bootgen '<Vitis>/bin/bootgen.bat' --output tmp/boot_new
```

原始ECG与官方手册不随Git复制。准确性全记录回归需按data/README.md和协议先获取对应公开数据；模型对照重放见docs/model_training_handoff.md，不读保留独立患者，不恢复训练。软件依赖和许可见docs/dependencies.md、docs/licenses.md。

## 接手时必须保留的边界

- 500Hz源输入保持500Hz；内部适配与500Hz事件/源时轴分开，不能要求采集端改360Hz。当前阶段只是开发回归与有限数字实板，不是临床设备或独立泛化合格。
- 原105风险与全部失败证据保留。不要把计划里旧失败/已被后续完成项覆盖的未勾框当新任务重跑；当前优先级看本页，再到专题计划/记录追溯。
- 新QRS在ARM，既有PL原检测器/AXI/FIFO用于独立smoke，PL尚无CNN。部分旧源码注释曾写“送PL”，以实际调用/BD和当前说明为准，不为了改一条注释伪改已验ELF来源。
- 根README.md、docs/materials_review.md不随整理改；用户数据/历史/备份不删除，工具派生与失败留tmp，不复制到Git。
- report是计划/报告，docs是操作/协议，docs/records是过程/验收，model是训练，src是正式实现，board/build/sim是运行/构建/验证入口，releases只保留当前交付文件，history本地忽略。
- 匹配镜像和源码SHA是发布门禁；改功能后新建证据与版本，旧latest原样归档。Flash编程必须获得操作者授权；QSPI复位不写Flash，但不能当第二次物理冷启动。
