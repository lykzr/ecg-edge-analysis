## 已确认的数据路线



`ADS1292R → STM32 → JDY-18蓝牙 → 配套USB接收适配器/电脑 → 板载USB_UART → Zynq`；Zynq经同一USB_UART把运算结果返回电脑。电脑保存/显示原始数据并中转，Zynq执行板端运算；不把PC运算替代ARM/FPGA对比。采集连接与USB_UART独立；型号和无线接收路线已由用户确认，实际设备身份、连续负载及断连行为仍待验。



协议分开维护：芯片SPI、厂商采集帧、[电脑输入ECG-IN-1](../docs/bridge_protocol.md)、Zynq结果ECG-UART-1。10/34字节差异只属于厂商段。500Hz有限合成流和修复版双向数字回放已有实板证据；真实无线、持续负载与人工GUI仍待验，不能据此勾选整机完成。

### 2.5 联调行为与最终演示验收细节



以下细化B01/B03—B06/B08—B15，不新增平行任务。优先先落实输入/位置/异常恢复，再扩大功能；详细采集约定见[采集计划1.4](capture.md#14-联调前必须补清的验收细节)，模型输入与延迟见[模型计划3.6](model.md#36-实际输入与整机延迟的验收细节)。



- [ ] **B04/B09/B10/B11与C13，启动/缺口/恢复（优先）**：列明启动预热、前后窗不足、有效运行、源丢样/发送缺口、断连/重连及复位后状态。先判明丢的是源样本还是PC显示数据；源样本缺口须判定哪些滤波/QRS/RR/心拍历史受影响，明确作废、重置或继续及恢复条件，不能把所有UART丢帧都当采样中断。缓存不完整时不强行分类；首个RR未知、旧心率/类别的过期显示和恢复等待须明确。用故障注入核对状态/计数及日志，不混接新旧会话或用N类掩盖未知。

- [ ] **B05/B06，CNN与PS接口**：冻结输入/输出张量布局、心拍编号、写入/启动/忙/完成/读回/应答、队列与背压、超时/错误和复位语义，定义半次输入或未完成输出如何处理；通过连续心拍和异常中断验证无串号/覆盖。寄存器、片上缓冲或DDR/DMA路线待选；若采用DDR/DMA，再验证地址/长度/对齐、完成同步及缓存一致性，不预设现有硬件具备这些接口。

上述行为若需要新增状态字段，先同步协议版本/能力与两端解析，再实施；本文不暗示现有ECG-UART-1已能表达全部异常。不默认加入看门狗、心跳停流或自动复位，先规定故障可观察与恢复行为，避免覆盖故障证据。
