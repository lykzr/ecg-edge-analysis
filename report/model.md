### 3.1 当前基础

轻量1D CNN指对单维心拍波形学习分类的卷积网络；训练在PC完成，推理是用固定权重计算类别。浮点模型、INT8整数参考与FPGA硬件推理是三个阶段，训练结束不等于硬件部署。

已有固定模板基线、可训练CNN、扩库、患者三折CV、目标来源微调/比例校正和因果历史背景尝试；严格N/S/V/F四分类仍未合格。来源/许可明确的小型网络为主方案，[CLEF-Small](../docs/model_candidates/clef_small.md)仍是暂缓备选。当前训练暂停、拟交接队友，负责人未确认；本轮不恢复训练或安装依赖。

- [x] 已选失败开发基线的三折小型复核包已准备，143,916个已知开发预测权重重放一致（2026-10-17）；见交接审查。不代表合格最终模型、独立测试或另一电脑复现，C12整体仍待完成。

**基线/对照组的目的**是回答“新方案是否比固定参照更好、改动是否起作用”。公开模型可用来复现对照，也可作为部署候选；不需要同时从头发明网络和复现所有候选。标签/专家标注是评分依据，对照模型不是正确答案。来自别人的权重还要核查其训练数据是否包含本项目测试患者，不能带着泄漏作独立对照。

**浮点与量化分别冻结、分别评估**：可以先用开发验证集检查量化可行性，不必为了试INT8提前开封测试；若最终同时报告浮点/INT8独立成绩，先固定两个版本与比较规则再统一评估，不看测试结果选量化参数。量化不合格要保留原结果，不能修改测试门槛掩盖。

当前恢复后的首要工作应是C01—C06的已有结果核对与失败定位，而非重新下载一遍或直接增加训练轮次。C07—C09以可验证的改动假设迭代；C10须满足预定开发门槛和冻结条件才进入。这里是完整计划，不是本轮训练授权或对达到某准确率/时长的承诺。

### 3.3 与采集、主体的交接及评估边界

信息采集A06/A07给出原始/滤波输出格式与群延迟，模型侧C05明确实际需要哪一路、预处理和窗口；训练数据与设备输入的幅值/导联/采样率不能默认为相同。B04负责系统自动切拍，模型侧负责窗口/归一化要求和可用性核查。C11交付整数参考，B05实现FPGA算子/缓存/传输；C12交可重建模型，C13与B11联合验收。

检测评估归B03/B07，包括TP/FN/FP、定位/RR误差及逐记录/类别/时间块；滤波验证归A06/A08，分类评估归C09/C10/C13。用户要求准确性重测时，对对应完整输入重跑，不能仅导入/哈希检查。若加入具体节律筛查，要另立任务/标注/窗口/指标，经确认后纳入，不从四类直接推导疾病。

### 3.5 网络规模与Zynq-7020部署选择

不能把“当前小模型未达标”直接解释为板子带不动，也不能据此认定小模型已经足够。训练在电脑完成，7020负责最终推理。允许评估比当前网络更强的结构，但以跨患者逐类收益、可量化性和实际部署预算决定，不以层数或“高级”名称选型。

硬件依据：Zynq-7020官方规格列220个DSP、4.9Mb块RAM，见[AMD DS190](https://www.amd.com/content/dam/xilinx/support/documents/data_sheets/ds190-Zynq-7000-Overview.pdf)。这是芯片总资源，不是本系统剩余可用资源；缓存、定点累加、接口和其他处理模块也需占用。运算复用及外部DDR可作为部署方案评估，不能据总资源直接承诺某网络实时运行或指定最大参数量。

当前已选开发基线为12,452参数、每心拍606,616次Conv/Linear乘加，来源[model/baseline原始结果](../model/baseline/residual_verified/fold_0/result.json)。这个预算不含预处理、激活/归一化、池化、传输和切拍等待，不是INT8实现成本或7020综合/实测；目前没有CNN硬件占用证明资源已到上限。

执行顺序与验收：

- [ ] C03/C05/C09：先核对S/F患者覆盖、跨库形态/标注/幅值、输入处理与逐类误判，判断是否存在数据或实现问题；不默认归因模型太小。
- [ ] C06/C07：保留当前小网络为固定对照，按明确假设尝试适度增加通道/残差层，或调整可用时间范围。保持数据角色/评分口径一致；改窗口或预处理须另立实验版本并预算新增等待，不能把多项改动收益混为结构收益。
- [ ] C08/C09：用患者隔离开发验证比较逐类精确率/召回/F1、macro-F1及稳定性。新结构没有可复核收益时保留失败，不靠加深或延长训练继续堆复杂度；不使用独立6人测试挑网络。
- [ ] C07/C11与B05：对有开发收益的候选核算权重、峰值激活/缓冲、算子/位宽/累加、乘加、传输及延迟，再评估INT8逐类损失与硬件可实现性。参数量不能替代片上内存/吞吐预算，只有综合/实现和板上结果才能确认资源/速度。
- [ ] C10/C12/C13：在预先冻结的质量、量化损失与部署预算下选最终版本，再做独立测试和端到端核验；不为了利用更多资源而换更大模型，也不以模型很小替代质量门槛。

当前协议的参数≤100k属于已有工程门槛，不是7020物理极限；如果候选需超出，应先提出预算与协议变更，确认后另立版本，不悄悄放宽。这里只把“允许适度增强、质量与部署共同选型”写入计划；训练暂停、现有失败结论和独立测试边界保持，不自动恢复训练或启用CLEF路线。

### 3.6 实际输入与整机延迟的验收细节

以下细化C01/C03/C05/C07/C09/C13中的输入、等待与未知出口，不新增模型任务或恢复训练。与[采集计划1.4](capture.md#14-联调前必须补清的验收细节)、[主体计划2.5](system.md#25-联调行为与最终演示验收细节)共同验收。

- [ ] **C05与A03/A06/A07/B04，训练到设备的一致性（优先）**：形成可执行的输入转换规范，列原始/滤波来源、通道/极性、单位、采样率转换/抗混叠、128点窗口、差分/历史RR和归一化拟合/应用方法。用同一段允许的数据把采集适配→PS预处理→模型输入逐阶段与软件参考比对，先冻结容差。明确训练和实际是否采用同版滤波，不能把“已滤波更干净”视为旧权重适用证据；群延迟/样本编号映射用于切拍和显示，不拟合标注。预处理改变另立版本，在开发验证集复评，独立测试不参与调整。
- [ ] **C07/C13与B13，等待和异常出口**：当前约533ms后窗属于已有输入协议的等待预算，并非板上实测；说明QRS事件何时可用、后窗何时齐全、推理何时开始与结果何时显示，避免把等待藏在采样阶段。评估启动不足、源缺口、削顶/无信号及低质量输入对归一化、RR和分类的影响；明确无效拍/未知输出、是否需要重建历史和恢复条件，不把未提供信号当正常N或把旧分数当当前结果。范围外识别能力需要单独证据，不以softmax分数直接宣称已实现。

### 3.7 检索后的训练方法审查（不恢复训练）
