# 三分钟功能演示：剪辑规划与旁白

适用素材：已录制的静息边采边测、深蹲后边采边测；每组都有手机拍摄的人员/操作画面和电脑录屏。用户已确认两组视频均使用 FP32 CNN 神经网络。本文未观看原视频，未读取这两次实际测量结果；加速比先用既有 FP32 板测的约 4.17 倍作剪辑占位，定稿时按对应录屏替换。所有方括号均为待按原素材填写的内容。视频总长 180 秒，以真实操作为主，不需要制作讲解 PPT。

## 1. 整体剪辑思路

故事线：**静息状态采集 → 实时分类与板上加速 → 深蹲后再次测量 → 两次结果对照 → 真实硬件实现与开源交付**。

电脑录屏占主要画幅，手机画面用于证明实际人员、采集设备、板卡与操作之间的联系。关键数值用局部放大，使观众能读清，不要把整张桌面缩进画中画。首次点击“开始并记录”时对齐手机鼠标操作与录屏画面，之后用原采集时间、波形和计数持续变化维持对应关系。

两次测量都以静止、姿态稳定后的实际片段为主。“深蹲后测量”不能写成“运动中抗干扰检测”。全 N 类只说明模型输出，不表示受试者健康或系统诊断正确；运动前后心率是否改变、改变多少，必须按实际记录说明。

## 3. 可直接录制的连贯旁白

以下按上一节顺序配画面，约 680 字。不是从头不停念到尾：在波形更新、深蹲和页面切换处留白。约 4.17 倍是剪辑占位，发布前替换成对应录屏的实际值；心率填实际数字。如果画面中不一致为 0，可以加一句“本次已对比心拍中，ARM 与 FPGA 输出均在设定容差内一致”。

> 这是我们基于 Zynq-7020 的心电边缘检测系统。接下来，通过静息和深蹲后的两次实际测量，展示边采边测与 FPGA 加速。
>
> 首先进行静息测量。ADS1292R 模块采集心电信号，电脑接收数据后传给开发板。板上的 ARM 处理器完成预处理和心拍准备，FPGA 负责 CNN 神经网络的核心推理。选择 FP32 精度和边采边测，点击开始并记录。
>
> 可以看到，心电波形随着采集持续更新，系统逐拍返回心拍位置、心率和分类结果。当前心率约为每分钟[静息心率]次。这里显示的 N、S、V、F 是四类心拍标签；首拍或窗口不足时，系统保留未分类。
>
> 再看加速对比。同一个心拍会依次在板上的 ARM 和 FPGA 中运行，系统分别计时，并核对输出。随着有效心拍增加，累计时间与加速比持续更新。这里的 FP32 CNN 神经网络计算，FPGA 相对 ARM 约加速 4.17 倍。这个计时包含板内寄存器传输，不包含采集等待和串口通信。
>
> 结束并保存第一轮记录后，受试者进行深蹲，恢复稳定姿态，再次开始测量。第二轮仍使用相同的 FP32 CNN 神经网络和边采边测模式。
>
> 现在心率约为每分钟[深蹲后心率]次，波形、逐拍分类和累计计时继续更新。两次记录的心率分别为[前]和[后]次每分钟，系统保存了对应的波形与结果，方便后续回看。这里的模型分类是研究输出，不作为健康诊断。
>
> 最后，这是对应硬件的 Vivado 实现页面。CNN 神经网络加速核心运行在 FPGA 的可编程逻辑中，设计时钟为 100 MHz。资源报告展示硬件实际使用的逻辑、存储与运算资源。
>
> 项目源码、硬件工程、实测记录和复现脚本均已开源。

## 4. 按实际结果选择措辞

### 心率对比

如深蹲后数值确实较高，可说：

> 深蹲后，这次记录的心率从每分钟[前]次上升到[后]次，系统实时呈现了这一变化。

如差别不大或第二次已恢复，不要强行制造“上升”故事，可说：

> 两次记录的心率分别为每分钟[前]次和[后]次，系统保存了两个独立会话的波形与分析结果。

若只有屏幕末尾当前心率，字幕写“结束时当前心率”；若会话确有平均值，才写“平均心率”。不能拿正常片段最低心率对深蹲后最高心率，再称会话平均变化。运动不产生可控的异常心拍，不把深蹲当作验证 S/V/F 的方法。

### 全部 N 类时

建议说：

> 本次有效心拍主要被模型判为 N 类，逐拍结果已记录。

避免说“全部健康”“诊断完全正常”“准确率 99.9%”。网页模型概率不是准确率，ARM/FPGA 不一致为 0 也只说明工程输出一致，不能证明诊断正确。

### 加速比及 INT8

- 现有片段如果是 FP32，使用该片段实际倍率，约 4.17 倍的录屏就讲约 4.17 倍，不配约 9 倍字幕。
- 现有片段如果是 INT8，使用本次实际倍率；已保存受控测试约 9.015 倍不能冒充这轮人体采集的实际结果。
- “累计含传输加速比”和“累计计算阶段加速”是两种计时口径，主展示选择前者。传输只含板内 AXI 寄存器访问，不含 ADC、无线、USB_UART 或浏览器。
- INT8 面板若确实录到，可补一句：“同一心拍还比较量化前后的时间；类别变化与同精度硬件不一致分别统计。”不能宣称零精度损失，已有合成测试存在跨精度类别变化。
- 若两次精度不同，心率仍可按记录各自展示，但加速表必须分开标 FP32/INT8；不能把两次倍率差解释为运动导致的变化。

## 5. 剪辑时的操作说明

1. **优先保证字能看清。** 视频建议 1920×1080。录屏中的心率、类别、拍数、累计时间和加速比各保留一次近景；不用鼠标快速来回圈画。
2. **手机与录屏同步。** 以点击开始、第一次波形出现、停止保存等共同事件对齐。交叉剪辑可以，但不要把另一轮数字拼进当前连续过程。
3. **留出连续证据。** 两轮至少各留 8–12 秒未经时间压缩的波形/拍数更新片段；其他等待可跳切，字幕写“过程节选”。若加速播放，明确标“×倍速”，同时不要修改界面计数。
4. **深蹲镜头适量。** 只需让观众知道实验条件变化，5–8 秒足够，主要时长给测量和计算结果。画面如未拍到运动过程，可用“深蹲后测量”的文字交代，不补造过程。
5. **少旁白覆盖数字。** 讲到心率或倍率时暂停移动画面，让该数字稳定可读；不必念所有参数。音乐音量明显低于旁白，点击、开始、停止可保留少量现场声。
6. **字幕为短句。** 名词首次出现解释一次：CNN 是神经网络，ARM 是板上处理器，FPGA 是可编程逻辑。整段技术说明放报告，不塞进画面。
7. **以实际输入命名。** 直接 ADS 输入写“实物采集”，保存文件回放写“CSV 回放”；合成输入写“合成信号”。同一片段中不要混用。
