# PC波形监视器

当前实现用Python标准库和Tkinter提供演示、ECG-UART-1日志回放、Windows串口只收、USB身份识别、厂商CSV/蓝牙采集及双向中转子窗口。演示/回放无需板卡，不依赖PySerial或新装绘图库，不执行模型。主窗口只收模式不发送板端命令；独立中转窗口使用ECG-IN-1送样/确认。500Hz有限合成流及[双向数字回放](records/bridge_board_20261020.md)已有上板证据；真实蓝牙、持续负载及人工界面仍待验。

## 启动界面

在项目根目录运行，选择带Tkinter的Python3.10或以上版本。当前本机已验证的解释器为：

```powershell
& './tmp/qrs_benchmark_env/Scripts/python.exe' -B src/ui/main.py
```

界面从上到下分为：标题与**运行状态徽标**、当前来源说明；操作区（离线来源 / 板卡串口 / 本次记录）；心率、RR、类别、累计样本、事件数五个数值卡片；波形区；底部“最近事件”和“诊断详情”两个分页；最后一行状态栏显示记录目录、停止原因或错误。

界面源码集中[src/ui](../src/ui/README.md)：main.py为入口，monitor.py/capture.py/bridge.py为三个窗口，plot.py为共享绘图；协议、串口、数据与中转后台留src/pc。旧src/pc/ecg_monitor.py无参数仍转交新UI，--headless命令保持兼容；整理后请关闭旧客户端再启动，不在运行中的Python进程内热更新模块。

| 徽标 | 含义 |
| --- | --- |
| 未开始 | 刚启动，尚未选择来源；空白波形区显示操作引导，不是故障 |
| 合成演示中 / 日志回放中 | 正在处理数学合成源或离线日志 |
| 串口已打开 · 等待数据 | 句柄已打开，但尚未收到字节或尚未收到合法H报文（会话头）；不显示单位或猜测波形 |
| 串口接收中 / 暂无新数据 | 已有合法会话；超过2秒没有新字节时提示“暂无新数据”，不据此判定断连 |
| 已停止 · 显示历史数据 | 手动停止或数据处理完；数值卡片标注“历史数据（已停止）” |
| 已停止 · 出错 | 打开、读取、记录或关闭失败；原因显示在底部状态栏（红色） |

未提供的数值显示“未知/未提供”：会话未声明分类能力时类别为“未提供”，分类值为?时为“未知”，都不显示为N。演示时事件表列名为“标记位置（演示）”，心率卡片注明来自演示标记间隔。协议计数、缺口、板端丢弃统计、最近解析错误、串口字节数及记录目录集中在“诊断详情”分页。

界面操作：

1. 点**开始演示**，查看60秒数学合成波形及指定位置标记；这没有运行QRS或CNN，不是设备实测。
2. 点**停止并保存**，保留原始字节、样本/事件CSV及摘要。再次开始会建立新目录，不覆盖旧记录。
3. 点**打开日志回放…**，选择本程序保存的raw.log或同版协议的板到PC行日志。回放按序快速处理，不模拟真实采样墙钟速度。
4. 点**导出SVG…**保存当前显示范围的矢量图。SVG只是补充，不能替代原始记录；没有PNG导出，厂商CSV从独立采集/中转子窗口导入，不能当作ECG-UART-1日志打开。

窗口可缩放，波形按Canvas实际尺寸绘制，窄窗口时“本次记录”按钮组换到下一行，说明文字随窗口宽度换行。Windows下启动时声明DPI感知，边距和表格行高按实际DPI放大；150%等缩放下的实际观感仍需人工查看。

## Windows串口接收

1. 关闭Vitis串口终端、其他串口助手等占用端口的软件；JTAG连接与串口终端是不同用途。
2. 点击**识别端口**刷新候选，选择实际板载USB_UART（首次多个候选须手选），点**连接并记录**；身份记忆规则见下文。界面固定115200/8N1/无流控，此只收模式不发送START/STOP/RESET，不清空驱动接收缓冲；DTR/RTS设为禁用，不主动发复位脉冲。实际USB桥打开时是否产生电平瞬变仍须实物核对。
3. “串口已打开 · 等待数据”仅表示成功打开句柄。发送端须提供合法H后才能解码W/E/T；若中途连接错过启动H，程序保存原文并等待，不推断元数据或自动复位。后续PS应用需要实现适当的H重发/查询策略，当前PC没有命令发送。
4. 点**停止并保存**关闭端口并完成摘要。再次连接新建记录和解析状态，不拼接上次未完成行，不自动重连，也不据空读判定设备拔出。

驱动报告溢出/帧错或读操作失败时停收并记录错误；不将其换算成不存在的源丢样数量。界面显示距最后收到字节的时间，停止后显示的波形/心率是历史值；没有字节不等于确认板卡停采。没有合法H时不显示上次会话的单位/数值。

实现采用微软[串口句柄规则](https://learn.microsoft.com/en-us/windows/win32/devio/communications-resource-handles)、[DCB配置](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-dcb)及[立即返回超时](https://learn.microsoft.com/en-us/windows/win32/devio/time-outs)。每40ms事件循环最多读取4096字节，无等待凑满；落盘与绘图仍在同一事件循环，慢磁盘/调度可能造成驱动积压，不能据此承诺连续满负载不丢字节。需板端上线后测实际负载/连续时长，若不满足再依据证据拆分工作线程/队列。

默认输出在tmp/pc_monitor_logs下的独立会话目录。顶部明确显示演示/文件来源；界面上的SYNTH/REPLAY/ADC是元数据声明，不是本机认证的实物来源。没有滤波/模型时不造滤波曲线或N类标签；未知电压比例显示“码值（未标定）”，未知采样率不生成秒轴。

旧smoke日志只有BEGIN/PASS/FAIL等自检文本，不含H/W波形帧，打开它不会凭空显示ECG。无波形时程序保留原日志并提示，不应把它理解为smoke未通过。

## 无界面复现

输出目录必须尚不存在，替换新的英文目录名：

```powershell
& './tmp/qrs_benchmark_env/Scripts/python.exe' -B src/pc/ecg_monitor.py --headless --demo --seconds 10.01 --output-dir tmp/pc_demo_new
& './tmp/qrs_benchmark_env/Scripts/python.exe' -B src/pc/ecg_monitor.py --headless --replay tmp/pc_demo_new/raw.log --output-dir tmp/pc_replay_new
& './tmp/qrs_benchmark_env/Scripts/python.exe' -B src/pc/ecg_monitor.py --ui-self-test --output-dir tmp/pc_ui_check_new
& './tmp/qrs_benchmark_env/Scripts/python.exe' -B -m unittest discover -s sim -p test_pc_monitor.py
& './tmp/qrs_benchmark_env/Scripts/python.exe' -B -m unittest discover -s sim -p test_pc_serial.py
# 以下会打开指定实际串口；只在需要连接设备时运行，目录必须不存在。
& './tmp/qrs_benchmark_env/Scripts/python.exe' -B src/pc/ecg_monitor.py --headless --serial COM14 --baud 115200 --seconds 60 --output-dir tmp/pc_serial_new
```

演示参数--fs/--scale只控制数学源，默认360Hz、scale=-1（未标定）；当前板端合成流及双向输入为500Hz，两者不是同一来源。要检查声明单位换算，可显式设置--scale 4096；这不代表真实ADC已经校准。演示事件由SYNTH-MARKERS指定，不是当前PL算法输出，也不能用于检测准确率报告。

--ui-self-test创建隐藏窗口，检查空白引导、停止后历史标注、Canvas波形/事件图元不越界和未知值显示后退出，不连接串口；它不等于人工视觉检查、人工交互或实物联调验收。

## 记录、限额和失败

| 文件 | 内容 |
| --- | --- |
| raw.log | 逐字节保存传入数据，包括坏行/未知行，不做换行或编码改写 |
| sessions.jsonl | 合法会话元数据；同会话相同H重发不另开会话 |
| samples.csv | 会话/来源/检测器、fs/scale、uint32序号及展开位置、名义时间、raw/filt及可用mV换算 |
| events.csv | 原始事件号、候选位置、RR、心率、类别/分数；没有可确认时间映射时不猜事件时间 |
| status.csv | 状态字段；FIFO事件丢弃、源采样丢弃和发送丢弃分别保存 |
| summary.json | 结束原因、累计解析/样本/事件/缺口计数、最后元数据及关闭错误；input记录输入方式，串口另含端口/波特率/收字节数/最后到达时间和错误 |
| waveform.svg | 无界面成功处理后的当前显示缓存图；GUI通过按钮导出 |

未知数值在CSV中留空，类别未知保留?；原始raw=-1/0仍是正常值，不能解释为缺失。样本时间由展开后的序号/fs生成，是逻辑采样时间，不是串口到达时间。接收首批之前的缺失数量未知，不补造缺口；重复或倒序帧计错且不推进序号。图中跨缺口断线，事件只在实际接收到的相应位置上标记，允许事件先于波形到达。

显示缓存最多4096点、256事件、20条日志；完整已接收记录仍写磁盘。输入按块读取、单行最多256字节、单文件最多256个不同会话；不同session切换显示缓存，禁止新会话后重用旧ID，同ID改元数据计错。源/滤波群延迟未定时不自动对齐或拟合偏移。

原始与解码文件累计默认64MiB，--max-bytes可配置、最少1024。到达上限、文件错误或磁盘写入失败时停止并保留已有文件，summary另占少量空间；磁盘完全写满时摘要本身也可能写失败，界面/命令行会报错。本轮不自动滚动、不删除历史，最终连续采集保留策略仍可再评审。限额停止时原始日志可能已保留最后一块、但CSV只写完其前半部分，结束原因必须一起检查，不能当完整采集通过。

CLI退出码0表示程序完成有效波形处理，不意味着输入无坏行或设备验收通过；查看summary计数。限额、I/O错误或没有协议波形返回非零。达到限额后的残留原始输入可在新目录重新回放，不能覆盖原失败目录。

串口无界面模式的--seconds是本次PC收取时长，不是板端采样时长，也不是正式验收门槛；Ctrl+C尽量关闭端口并保存，退出码130。记录失败/驱动错误返回2；无论已有多少有效样本都不能将错误退出当作连续验收成功。打开端口后尚无H仍保留原始字节，smoke的Hello World/BEGIN/PASS文本不能变成协议波形。

## 协议与范围

当前PC软件规则见[UART协议](uart_protocol.md#13-pc软件v1实现约定)，它在旧草案上补充session/source/detector、W的实际批量n、分开的丢弃计数。旧6字段H/无n的W只是此前草案，本程序不静默猜格式。无行校验基线已明确；此版不接受声明LINE_XOR的输入，不自动尝试多种校验。

板卡结果视图继续按同版ECG-UART-1解析；厂商采集走下文独立视图，不能把34字节原文送入结果解析器。真实fs、增益、物理单位及滤波来源/延迟仍需核查。独立接收应用已完成有限数字回放上板；无线连续采集和人工GUI仍待验，不合入已通过smoke镜像或自动更新release。实际验证记录留docs/records。

## 采集与厂商CSV

启动方式不变：

```powershell
python -B src/ui/main.py
```

主窗口点击**采集 / 厂商CSV…**，打开同一客户端内的采集子窗口。主窗口的板卡接收会先停止并保存，采集窗口打开期间禁用主窗口板卡连接按钮。旧演示、ECG-UART-1日志回放与结果接收继续保留；本轮采集窗口不连接或向Zynq发送数据。

### 厂商RawData回放

1. 点击“打开厂商CSV…”，选择ADS1292R_ECGRawData一类五列波形CSV。HeatData是参数摘要，当前不作为波形导入，其参考视图另行实现。
2. 文件必须包含timestamp(s)、resp_raw、ecg_raw、resp_filtered、ecg_filtered五列，原码为0～16777215整数；时间须按500Hz连续递增。缺列、空值/非有限数值、时间缺口或错误行会停止留证，不补零或压紧时间。
3. 按500Hz逻辑时间回放：上图心电CH2，下图呼吸CH1。默认查看减8388608后的有符号码；切换“厂商滤波”只显示CSV原有浮点列，不重新滤波或再次减偏移。纵轴为未标定码值，不显示mV。
4. 点击“停止并保存”可中止；重新开始会创建新目录。停止后曲线保留并标历史数据，后台完成关闭后才允许重新开始。关闭主窗口也会等待采集后台退出和记录关闭。

### USB蓝牙采集

1. 关闭占用接收适配器的厂商软件。在采集子窗口点“刷新”，检查实际端口、描述及USB实例。唯一CH340类设备可自动提示候选；多个候选时自行选择，不固定COM4。已知主窗口Zynq端口会排除；程序不会打开其他端口或发送探测命令。相同USB实例变更COM后可随刷新更新，连接前重新核对当前身份。
2. 确认采集设备使用本套资料的34字节四点格式，点击“连接采集并记录”。采用115200/8N1/无流控，按CH2心电/CH1呼吸恢复偏移码；不读取或证明板上固件版本，不修改设备配置。
3. 起始需找到连续三帧满足34字节及24位码值约束的候选边界。初始前缀仍完整保存于capture.bin，并记录跳过的字节数；这些字节不换算成已知丢样点数。达到4096字节仍无候选、候选相位冲突、开始收到数据后五秒仍未锁定，均停止。锁定后坏帧直接停止，不扫描丢字节重同步。
4. 无CRC/源序号意味着合法形状的误码仍可能漏检；候选对齐、PC编号和曲线连续不证明ADC/无线无丢样。超过两秒无新数据只提示“暂无新数据”，不冒充已判定断连。驱动错误、记录超限或写盘错误停止并保留已有数据。
5. 实时串口没有提供滤波列，选择“厂商滤波”显示未提供。这里不执行心率、呼吸率、QRS或CNN计算，也不复用厂商登录/联网认证。

### 记录与算法预览

默认每次在tmp/pc_capture_logs/新建目录，总数据限额64MiB，限额停止而不删除历史。后台独占来源并完整写盘，界面只取最近4096点、展示最多2500点；像素桶保留极值，显示抽点不删减完整记录。

| 文件 | 内容 |
| --- | --- |
| source.csv | 本次实际读取的厂商CSV原始字节；只有完整回放到EOF才是完整副本 |
| capture.bin | 实际收到的蓝牙串口原始字节，含初始前缀和残帧 |
| samples.csv | PC连续编号、软件时间、两路原始偏移码/有符号码及可用的厂商滤波列 |
| normalized.csv | index/sample两列心电int16算法预览；不在此阶段发送Zynq |
| summary.json | 来源/设备身份、资料配置、转换位移、削顶、状态/错误、候选前缀及尾部、未知源丢样和读入摘要哈希 |

右移默认8位，是完整有符号24位范围映射到int16的可复现预览，不是物理单位标定或最终检测器幅值合同；可显式调整0～23，超界饱和并计数，原24位数据始终保留。滤波浮点列不直接作为int16输入。完整来源与转换参数随记录保存，失败时检查summary原因及尾部，不把失败前的局部文件当完整采集。摘要文件少量空间不计入64MiB；磁盘全满仍可能导致摘要无法写出，界面会显示错误。

仅CSV无界面验证可运行：

```powershell
python -B src/pc/ecg_capture_core.py --csv '<厂商RawData.csv>' --output-dir tmp/capture_csv_new
```

该命令快速读取，不等待实时节拍，不打开串口；目标目录必须不存在。GUI默认实时回放，两者都不证明硬件节拍。真实蓝牙采集、人工布局和双向中转尚需实机验收；500Hz合成流有限运行的板上记录见[验收记录](records/stream_board_20261020.md)，不代替双向中转。

## 与电脑中转入口的关系

双向输入使用内置中转子窗口，独立[ecg_bridge命令行](bridge.md)仍保留；主窗口的结果只收模式不直接解析厂商帧或ECG-IN-1确认。中转目录results/raw.log可用“打开日志回放”查看；USB_UART由中转后台独占时不要再从其他窗口打开同一COM。

## 板卡端口识别

主窗口启动时只读枚举Windows活动串口及USB身份，“识别端口”可刷新；不打开串口、不发送探测、不自动重连。首次只有一个CH340类候选时可预选，多个候选须手选。CH340只说明转换器类型，不证明是Zynq；查看实际连接与设备描述，不能把USB蓝牙接收器当板卡。

收到合法结果会话后，程序将该USB实例保存至本机tmp/pc_devices.json。以后刷新时随同一设备的COM号变化；记住的设备缺席时留空，不回退连接另一个设备。连接前再核对身份，防止旧COM号被其他设备复用。USB实例也可能随接口/驱动变化，此时手选新设备再接收核对；自动提示不等于物理身份认证。文件仅本机派生配置，不进入共享仓库。

## 界面双向中转

主窗口点击“送样 / 双向中转…”，按[界面送样步骤](bridge.md#界面送样)操作。先用厂商RawData CSV，后用蓝牙来源；选择不同的Zynq与采集端口，右移默认8位，蓝牙本轮默认5000点。上图原始CH2，下图Zynq回传int16及黄色事件；电脑不运行检测或分类。原采集视图仍是只收，不因新增按钮暗中上传。

来源和USB_UART各由一个后台拥有；Tk每40ms读取有界快照，不直接操作串口。停止先关闭来源，再排空已记录的待送样本及确认；超时失败保存现场，不自动复位板卡。两图与事件用从0开始的源index对应；CSV原时间与转换参数随记录保存，不混用蓝牙到达时间。新记录目录tmp/pc_bridge_logs/，capture/为原码，results/为板端结果；根摘要中完成、确认、回传和源结束原因分别保留。

功能已完成软件闭环和使用GUI后台的CSV实板数字回放；实际双USB/无线来源、Windows人工显示及持续负载仍需验收，隐藏窗口不替代人工观察。板卡必须运行含计时修复的ecg_bridge而非ecg_stream，当前本机工作区为tmp/ecg_bridge_clock/vitis_workspace，重新运行要求见中转说明。
