# PC ↔ Zynq USB-UART 通信协议规划

> 状态：**规划文档**，2026-10-17 初版。协议尚未实现，PS 发送端与 PC 接收端都没有代码，也没有上板验证。文中“待定/不明”的条目保持空白，不预设结论。
>
> 关联：[工程计划](../report/project_plan.md)、[寄存器接口](register_map.md)、[HDMI 显示方案](HDMI.md)、[下载教程](download_guide.md)、[过程记录](records/lykzr.md)。

## 1. 目标与范围

目标：在 PC 与领航者 V2（Zynq-7020）之间，用板载 USB-UART（CH340）建立一条双向通信链路，用于：

- 实时演示：板端把心电波形、R 峰、心率/RR、分类结果送到 PC，PC 显示；
- 历史保留：PC 侧连续保存原始记录与解码结果，便于回看、核对与写报告；
- 后续联调：PC 发命令控制采集/回放（是否实现见第 5 节“待定”）。

不在本协议范围：固件升级（走 JTAG/QSPI）、图像/文件传输、音频、人体安全相关控制。

## 2. 角色与方向

- **板 → PC（主方向）**：波形批、心拍事件、状态遥测、日志、命令应答。
- **PC → 板（次方向）**：启动/停止/复位、查询状态、心跳（可选回放，见待定项）。

## 3. 已知约束

- 板载 USB-UART 为 CH340，PC 端表现为 COM 口；8N1，无硬件流控。
- 当前工程 PS 使用 UART0（MIO14/15）输出 `printf` 日志，默认 115200（见 [下载教程](download_guide.md) 与 smoke 说明）。
- 板上只有一路 USB-UART 到 CH340，**日志与协议数据只能共用同一条串口**，必须靠行标签区分（见第 8 节）。
- PL 侧目前没有“滤波后样本”的 AXI 可读寄存器；寄存器定义见 [register_map.md](register_map.md)。因此 `filt` 的数据来源需要先定（见第 5 节第 3 条）。
- 事件可从 AXI-Lite 的 FIFO 读取：位置 `0x08`、RR `0x0C`、序号 `0x18`、排队数 `0x1C`、累计丢弃 `0x20`，读取后写 `0x04` 弹出。
- UART 发送是阻塞还是中断/DMA，决定能否在 360/500 Hz 采样节拍下稳定发送（见第 11 节）。

## 4. 已定与建议的决策

| 项目 | 结论 | 来源 |

## 5. 不明/待定清单（写计划时保持空白）

1. 采样率：360 Hz 还是 500 Hz？（影响批量行长度与带宽预算）
2. 样本格式最终选 int16 还是 24 位原始码值？
3. 滤波样本的数据来源：PS 端复制一份滤波，还是给 PL 增加“滤波样本”AXI 寄存器（后者要改 RTL 并回归）？
4. 波特率是否最终提高（115200 / 460800 / 921600）？
5. 是否加行校验（异或/CRC）？是否加命令重传？
6. 历史保留时长、文件大小上限、滚动策略。
7. 是否实现 PC→板回放（MIT-BIH 数字样本回放）。
8. 一次演示的连续运行时长与 PC 磁盘空间预算。
9. 板卡是否需要在无 PC 时独立运行（影响心跳超时策略）。

## 6. 带宽预算（按批量行估算）

批量 `W` 行固定 8 个样本，每样本 2 个 int16（raw、filt），一行约 110～130 字节。

| 采样率 | `W` 行/秒 | 估算带宽 | 占 115200 可用量（约 11.5 KB/s） |
| ---: | ---: | ---: | ---: |
| 360 Hz | 45 | 约 5.0～5.8 KB/s | 约 43%～50% |
| 500 Hz | 62.5 | 约 6.9～8.1 KB/s | 约 60%～70% |

另加事件（约 1 次/秒）、状态（1 次/秒）与日志，合计仍有余量；命令应答很短。**若最终 500 Hz 且日志较多，再评估改 460800。**

## 7. 数据清单

**板 → PC**

| 数据 | 内容 | 频率 |
| --- | --- | --- |
| 波形批 | 样本序号、原始值、滤波值 | 每批 8 样本连续发送 |
| 心拍事件 | 事件序号、R 位置、RR（样本数）、瞬时心率、类别、置信度 | 每检测到一次 |
| 状态 | 心率、RR（ms）、类别、标志（OK/OVF/CLIP）、采样率、丢样计数、运行时间 | 1 Hz |
| 日志 | 级别、文本（启动、错误、状态切换） | 事件触发 |
| 命令应答 | 命令编号、状态 | 收到命令后 |

**PC → 板**

| 命令 | 说明 |
| --- | --- |
| `START` / `STOP` | 开始/停止数据流 |
| `RESET` | 复位协议状态与计数（是否复位检测器另行确认） |
| `GET_STATUS` | 立即回一帧状态 |
| `SET_RATE` | 设置采样率（参数待定；当前 RTL 参数是构建期固定） |
| `HB` | 心跳 |
| `P,...` | 回放样本（待定，Phase 2） |

## 8. 协议格式（v1，ASCII 行）

### 8.1 通用规则

- 每行以 `\n` 结尾，PC 端兼容 `\r\n`；
- 字段用英文逗号分隔，十进制整数/小数，无空格；
- 行首标签区分类型；**未知标签或格式错误只计数，不中断解析**；
- 单行最长 256 字节，超长行丢弃并计数；
- 数值统一：raw/filt 为 int16（-32768～32767），单位与比例由 `H`/`T` 行给出；
- 序号：样本序号 32 位从 1 递增；事件序号 16/32 位递增；PC 用序号跳变判断丢样/丢事件。

### 8.2 板 → PC 报文

```
H,<协议版本>,<固件版本>,<采样率或-1>,<scale>,<能力位>
W,<seq0>,<raw0>,<filt0>,<raw1>,<filt1>,...,<raw7>,<filt7>
E,<evt>,<rpos>,<rr>,<hr>,<cls>,<conf>
T,<hr>,<rr_ms>,<cls>,<flags>,<fs>,<drop>,<uptime_ms>
L,<level>,<text>
K,<cmd_id>,<status>
```

字段说明：

- `H`：握手，协议版本如 `ECG-UART-1`；`采样率或-1` 未定；`scale` 为 1 mV 对应单位（当前 4096）；能力位用十六进制位图，待定。
- `W`：固定 8 对样本；`seq0` 是本批第一个样本的绝对序号；`raw` 原始样本，`filt` 滤波后样本。
- `E`：`rpos` 为 R 峰绝对样本位置；`rr` 为样本数；`hr` 可带 1 位小数，未知写 `-1`；`cls` 为 `N/S/V/F/?`；`conf` 0～100，未知写 `-1`。
- `T`：`flags` 如 `OK`/`OVF`/`CLIP`/`DROP`，多个用 `|` 连接；`fs` 当前采样率；`drop` 累计丢样；`uptime_ms` 板端运行毫秒。
- `L`：`level` 为 `I/W/E`；文本不含逗号（或允许逗号但只取前几个字段，待定）。
- `K`：`status` 为 `OK`/`ERR`/`BUSY`/`UNKNOWN`。

示例：

```
H,ECG-UART-1,0.1.0,-1,4096,0
W,1001,-12,15,56,-3,-78,22,...
E,17,1004,300,72.0,N,90
T,72.0,833.3,N,OK,360,0,1234567
L,I,stream started
K,7,OK
```

### 8.3 PC → 板报文

```
C,<cmd_id>,<命令>[,<参数>...]
HB
P,<seq>,<raw>[,<filt>]
```

- `cmd_id` 由 PC 递增，板端在 `K` 行回显同一编号；
- 命令字大写；未知命令回 `K,<id>,UNKNOWN`；
- `HB` 每秒一次；板端是否据此停流见待定项；
- `P` 行仅 Phase 2 回放使用（待定）。

## 9. 时序与状态

- PC 连接后先收 `H`；若 2 秒内未收到，PC 可发 `C,1,GET_STATUS` 探测（行为待定）。
- 板端状态：`IDLE` → `STREAMING` → `IDLE`/`ERROR`；状态切换发 `L` 行。
- 板端 1 Hz 发 `T`；波形批按采样节拍组批发送。
- 命令应答延迟目标 < 100 ms；若波形帧正在发送，允许等一帧。

## 10. 可靠性与错误处理

- UART 无重传：PC 侧用样本序号/事件序号检测缺口，并在界面显示“丢样/丢事件”计数；
- 板端统计自己的发送溢出、组批丢弃、PC 命令解析错误，并通过 `T`/`L` 上报；
- v1 可选每行末尾 `*HH`（异或校验）；是否启用待定；启用后 PC 校验失败计错并丢弃该行；
- 坏行不阻塞后续解析；PC 端保留未知行计数与最后一条坏行，便于联调；
- PC 侧 UART 读取线程与界面线程分离，避免界面卡顿导致底层缓冲溢出；
- 长时运行需要文件滚动（见第 14 节）。

## 11. 板端（PS）实现要点

1. **发送路径不能阻塞采样**：当前 smoke 是“写 `0x00` 送样本 + 读 FIFO”。若在采样循环里直接 `printf` 一整批（约 120 B，115200 下约 10 ms），会拖慢 360/500 Hz 节拍。必须使用 UART 中断/DMA + 发送环形缓冲，或把批量降到可控大小并实测节拍。
2. **UART 复用冲突**：`printf` 与协议共用 UART0。方案 A：把 stdout 重定向到同一环形缓冲（推荐，日志变成 `L` 或原样文本行）；方案 B：流式期间关闭 `printf`，只发协议。两者都需确认不与 Vitis BSP 的 UART 初始化冲突。
3. **取数位置**：样本在写 `0x00` 的同一处取；事件在消费 FIFO 的同一处取；状态读 `0x24/0x28/0x2C/0x30` 与 `0x20`。
4. **滤波样本来源待定**：PL 目前不提供滤波后样本。若 v1 要发 `filt`，可选：PS 端复制一份参考滤波（不改 bitstream），或给 PL 增加可读寄存器（改 RTL，需回归六组 20915 周期黄金向量）。见第 5 节第 3 条。
5. **接收命令**：UART RX 中断 + 行缓冲状态机，解析 `C`/`HB`；未知命令回 `K`。
6. **采样节奏**：360/500 Hz 由定时器决定，不以 UART 发送完成时间为准。
7. **不改 AXI 寄存器语义**：UART 只是旁路输出；若必须新增寄存器，需同步 [register_map.md](register_map.md) 并回归。

## 12. PC 端实现要点

- 数据源：串口（Win32 API 或 pyserial）、文件回放、内置演示源（无板可用）；后续可加 TCP。
- 解析：行解析状态机、序号缺口统计、可选校验、坏行计数、未知行保留。
- 显示：心率/RR/类别大字、实时波形（原始/滤波可切换）、R 峰标记、事件历史表、连接与错误状态。
- 记录：原始行日志 + 解码 CSV + 事件 CSV（见第 14 节）；界面截图作为补充。
- 自检：离线自检（协议解析、坏帧、序号跳变）与隐藏窗口构建自检；无板也能验证 PC 端。
- 回放：从历史文件在 PC 上重放（不经过板子）属于 Phase 2；PC→板回放待定。

## 13. 与现有工程的关系

- 协议是 **PS 软件层** 功能，v1 不改 RTL/BD/XDC，**不需要重新生成 bit/XSA**；但重编 ELF 后 smoke 的 ELF 会变化，需重新确认 smoke 运行与日志。
- smoke 输出（`BEGIN…PASS` 等）与协议行共用串口：PC 端忽略非协议行并计数，因此 smoke 仍可原样运行。
- `register_map.md` 不变；若增加滤波样本寄存器或命令寄存器，必须同步更新并做 RTL 回归。
- HDMI 与 UART 可共用同一份 PL 样本/事件 tap（见 [HDMI.md](HDMI.md)）；PC 显示是 HDMI 的备份，不是唯一输出。
- `releases/latest` 不动；Git 仍暂停。

## 14. 历史记录设计（回答“直接存成图片行不行”）

**只存图片不行**：图片不能重放、不能逐样本核对、不能统计丢样/事件、也不能作为“实测数据”的证据。可行的组合是：

| 记录 | 格式 | 用途 | 说明 |
| --- | --- | --- | --- |
| 原始行日志 | `.log`（逐字节） | 精确重放与协议核对 | 主记录 |
| 解码样本 | `.csv`（time, seq, raw, filt） | 画图/分析/报告 | 主记录 |
| 事件 | `.csv`（evt, rpos, rr, hr, cls, conf） | 心拍历史/指标 | 主记录 |
| 界面快照 | `.png` | 演示材料、答辩截图 | 补充，可选 |

- PNG 可用标准库 `zlib` 自行写（不依赖 Pillow），或后续用 Pillow；具体实现待定。
- 文件默认放 `tmp/pc_monitor_logs/`，按“日期_端口_会话”命名；保留时长/大小上限**待定**（见第 5 节第 6 条）。
- 需要写进正式材料的精选记录，再按 [AGENTS](../AGENTS.md) 复制到 `data/` 或 `docs/records/` 并注明来源。

## 17. 风险

1. **UART 阻塞拖慢采样**：必须中断/DMA + 环形缓冲，否则 360/500 Hz 节拍不稳。
2. **`printf` 与协议共用 UART**：处理不好会出现日志与数据交错、甚至丢失；需要统一发送层。
3. **滤波样本来源未定**：不改 RTL 只能 PS 复制滤波；改 RTL 则要回归，影响面更大。
4. **115200 余量有限**：500 Hz + 日志多时需要 460800；PC 与板端波特率必须同步。
5. **CH340/USB 缓冲**：PC 读取线程卡顿会丢字节，序号缺口必须能看出来。
6. **未知项未冻结**：采样率、精度、校验、回放未定前不能写死实现。
