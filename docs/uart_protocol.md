## 4. 序号、位置和时间定义

### 4.1 样本与事件的统一基准

- `[建议]` W.seq0采用**0基uint32**，与当前PL位置一致；一批第i个样本的位置为`(seq0+i) mod 2^32`，i=0..n-1，n=1..8。废止旧草案“样本从1起”的无依据约定。
- `[事实]` PL没有样本计数读取寄存器。`[建议]` PS仅对实际成功提交给检测器的样本推进对应计数；源采集序号与检测器输入序号若不同，必须显式记录映射，不把采集丢点后压紧的编号当原始时轴。
- `[建议]` E.evt传FIFO原始32位序号，首事件1，保持因FIFO丢弃而产生的缺口；E.rpos原样传0x08，不做为提高分数而拟合的偏移。
- `[事实]` 32位硬件计数自然回绕时事件序号可为0，rpos=0也可为有效位置；FIFO是否为空由0x04状态判断，不能仅按这些字段为0丢弃有效事件。软件v1用session区分重启与自然回绕，见第13节。
- `[建议]` 同一会话内E.rpos与W.seq0属于同一个检测器输入序列。PC先缓存波形，再按位置标记；事件可能晚于对应W到达，或先于该批W到达，不能按串口接收时刻画点。
- 当前标记名称使用“QRS候选/检测事件位置”；以后精确R峰算法移植后，必须另行标识检测器版本并验证定位，不能换名称冒充同一算法精度。

### 4.2 时间与缺口

- `[建议]` 已知固定fs、连续同一输入序列时，相对样本时间为`index/fs`，RR毫秒为`1000*rr/fs`，心率为`60*fs/rr`；串口接收时间不等于采集时间。
- `[事实]` 首个事件rr=0表示没有前一事件；`[建议]` 此时hr/rr_ms报未知，不除零，也不显示为0心率。
- `[建议]` PC分别统计波形序号缺口、事件序号缺口、FIFO事件丢弃和解析错误；不知道原因的缺口不全部归为UART丢字节。
- `[软件v1]` 会话标识、回绕和乱序处理见第13节；PS重启/重新配置PL必须产生新会话，STOP/START不得隐式复位。真实计数同步与重连行为仍须在PS实现和板上验证，不跨未知会话拼接。

## 5. 能力位与缺失字段（软件v1采用）

### 5.1 能力位分配

H.caps表示固件**实现的协议功能**，不是实时健康状态，也不是“计划以后支持”。位号已用于PC软件，不是现有smoke固件事实。

| 位 | 名称 | 置1的前提 |
| ---: | --- | --- |
| 0 | RAW_W | 已实现原始样本W输出 |
| 1 | FILT_W | 有明确来源、单位和延迟对应的滤波波形输出 |
| 2 | EVENT_E | 已实现FIFO事件E输出；不承诺精确R峰 |
| 3 | STATUS_T | 已实现状态T输出 |
| 4 | CLASS_RESULT | 已接入并验证真实分类输出，不能用演示标签置1 |
| 5 | COMMAND_CK | 实现C命令解析与K响应；不意味着每个命令都支持 |
| 6 | 保留校验位 | 软件v1不支持，置1即拒绝H；不猜测算法 |
| 7及以上 | 保留 | 先置0；PC对未知位记录警告，不据此猜测报文扩展 |

`[建议]` 十六进制格式显式写0x前缀。未实现的功能位为0；能力缺失与实现后暂时无数据不同。当前smoke没有该协议H输出，因此不能给当前发布编造caps。

### 5.2 不可用值

| 字段 | 建议表示 | 校验/显示要求 |
| --- | --- | --- |
| raw | 必须是真实提供的int16值 | 整批无真实样本就不造W；0和-1都可能是正常原始值 |
| filt | 无来源/暂不可用写字面量NA | 有效时才是int16；缺失不能复制raw或填0冒充滤波；FILT_W=0时全部NA |
| fs/scale | 未知写-1 | 不生成秒/mV标尺；scale只在已核验物理映射时有意义 |
| E.rr | 首事件保留硬件0 | 它不是0ms有效心拍间隔 |
| hr/rr_ms | 未知写-1 | rr=0或fs未知时使用；界面显示未提供 |
| cls/conf | 未接模型时? / -1 | 有真实输出才使用N/S/V/F与0..100分数；分数不等于疾病概率或已校准概率 |
| flags | 监测状态整体未知时NA | 已实现的状态才能报告；词表及互斥规则见第13节 |
| 计数器 | 未实现的统计写-1；已实现且无异常为0 | 不用0冒充已测量无丢样 |

以上NA/能力位已用于PC解析；PS接入时必须使用同一版定义；目标数据“都发”没有被删掉，只是未实现值不能伪造。

## 6. 报文格式与解析规则

软件v1的完整规范见[第13节](#13-pc软件v1实现约定)。ASCII、LF结尾，兼容CRLF；单行最多256字节（含换行）。错误行计数并恢复，旧smoke文本只作为非协议原文保存。

```text
H,ECG-UART-1,pc-demo-1,example,SYNTH,SYNTH-MARKERS,360,-1,0xD
W,0,3,-12,NA,56,NA,-78,NA
E,1,1,0,-1,?,-1
T,-1,-1,?,NA,360,-1,0,-1,8
L,I,example only,not measured
```

以上是离线示意，不是设备输出或黄金检测向量。没有滤波、分类、电压标定或命令能力；FIFO/发送队列统计未实现报-1。此前6字段H、无n固定8点W及单一drop的T属于未发布旧草案，不兼容当前软件。

PC发命令尚未实现。后续最小接口拟采用`C,<cmd_id>,START|STOP|GET_STATUS`及`K,<cmd_id>,OK|ERR|BUSY|UNKNOWN`。START/STOP仅在同会话内启停传输，不隐式复位PL；GET_STATUS应返回同一H及T，不清计数。RESET/SET_RATE/HB/P不在本轮实现范围，无相应支持不得声称可用。PS实现前还须核对这些语义、无PC启动行为与驱动；解析K不等于PC已经发送命令。

## 7. 带宽预算的适用条件

`[估算]` 115200/8N1按每字节10串口位计算，理论上限11520字节/秒，不是实测吞吐。8对满宽int16、最大10位uint32序号、无校验时，W最长127字节（LF）或128字节（CRLF），其中包含n字段：

| 假设fs | W批/秒 | W最坏字节/秒（LF） | 理论串口占比 |
| ---: | ---: | ---: | ---: |
| 360 | 45 | 5715 | 49.61% |
| 500 | 62.5（平均） | 7937.5 | 68.90% |

这是两路有效int16的规划上界，不表示真实传感器已选360/500。另需预算H/E/T/L、命令、校验和缓冲峰值，不能固定假设事件仅1次/秒；滤波缺失写NA时当前行更短。余量不等于已验证无丢样，也不能据此自动升波特率。最终波特率/峰值日志负载与验收门槛见U06/U07。

## 8. 时序和PS实现约束

- `[建议]` 固件启动时发送H；**PC打开串口不必然令PS重启或触发H**。重连/主动查询/周期重发H及超时策略属于U03/U05，不无条件写死“连上2秒必收到H”。
- 合成源使用独立节拍；电脑送来的已采样数据按源序号/fs解释时间并有界排队处理，不把蓝牙/UART包到达时间当采集时刻，也不补造样本。
- 发送与采样解耦，设置有界队列并统计溢出；中断/FIFO非阻塞发送为候选。不能武断要求UART DMA，是否支持与如何使用须核对实际PS UART和驱动。缩短批量可降低单次阻塞，但不减少总字节量，不能仅凭“改小批量”保证节拍。
- printf与协议共用UART0时统一写出策略，避免字节交错；当前PS候选不调用printf/xil_printf，只由协议队列写UART0，原smoke不变。
- 事件消费者先读完整队首再出队，唯一消费者原则沿用寄存器表；不因PC显示刷新而暂停FIFO消费。
- 当前PS候选用全局计时器和有界轮询、T名义1Hz；这些选择尚未经过板上节拍/吞吐验收。命令未实现，不承诺响应时间，不将轮询路线强加给真实ADC接入。

## 9. PC显示、记录与验证计划

第2步先做离线解析与演示源/文件回放：验证字段范围、NA/未知能力、坏行后恢复、序号缺口、事件延迟到达、会话变化和记录重开。显示原始/可用滤波波形、QRS候选标记、心率/RR与错误状态；不拿演示标签冒充真实分类。

串口读取与显示绘图应避免互相阻塞，当前界面采用Tkinter事件循环，Windows接收适配每40ms最多读取4096字节、立即返回；记录/绘图也在该循环，真实串口负载与慢磁盘下积压尚未验证。当前不自动引入TCP或手写PNG编码。原始字节日志与样本/事件CSV为主要记录，截图可选；会话/固件/数据来源、单位、时间基准和丢弃统计随记录保存。

输出候选目录tmp/pc_monitor_logs/，文件创建不得覆盖旧会话；当前64MiB保护、停止保存与不覆盖规则见第13节，正式连续验收时长仍待定。精选证据才进入docs/records/，遵循Git日志白名单，不批量提交原始运行日志。

| drop泛称丢样，读取0x20 | 区分FIFO事件丢弃、源采样丢弃、发送丢弃和PC缺口 |
| 4096单位/mV是整条采集链已有事实 | 仅已转换数字输入适用，原始ADC标定另核 |
| 未确认就按真实采集360Hz | 未决继续标记；当前360仅作为已知构建/受控回放参数 |
| 500Hz加日志必升460800、事件固定约1Hz | 算预算与峰值实测后决定，不预先承诺余量 |
| 必须UART中断/DMA，缩批即可保证节拍 | 目标是解耦和有界缓冲，驱动支持/方法/节拍须验证 |
| 连接后必收H；RESET/SET_RATE默认可用 | 连接/重启分开，按实际能力冻结；无软件复位/运行时配置接口 |
| v1不改RTL，却同时保证PL滤波样本 | 两种滤波来源未决，若选PL输出则另做接口/回归 |

| 分类N/90示例、W含省略号像实测 | 示例完整且明确离线示意，分类未知?/-1 |
| “CRC留v2”、PNG手写zlib、PC必是HDMI备份 | 均非本轮已定要求，删除强制口径，保留需依据的未决项 |

## 13. PC软件v1实现约定

本节是当前[src/pc解析器](../src/pc/ecg_uart.py)采用的软件合同；第4—5节的“建议”凡与本节一致者已在PC采用，不能据此认定PS或采集端已实现。U01/U02继续待硬件依据；U03/U04的软件字段已决定，硬件计数同步仍需实测；U05命令未实现；U06采用无校验离线基线，最终实物波特率待测；U07已有软件容量保护，正式验收时长待定。

```text
H,ECG-UART-1,<firmware>,<session>,<source>,<detector>,<fs>,<scale>,<caps>
W,<seq0>,<n>,<raw0>,<filt0>,...（恰好n对，省略号只用于语法说明）
E,<evt>,<rpos>,<rr>,<hr>,<cls>,<conf>
T,<hr>,<rr_ms>,<cls>,<flags>,<fs>,<fifo_event_drop>,<source_sample_drop>,<tx_sample_drop>,<uptime_ms>
L,<level>,<text>
K,<cmd_id>,<status>
```

- 所有数据须先有合法H；firmware/session/detector是1—32位英文字母、数字、下划线、点或连字符。source为SYNTH/REPLAY/ADC/UNKNOWN，表示发送者声明，不能替代采集证据。fs是正uint32 Hz或-1；scale是正uint32码值/mV或-1。caps为0x加1—8位十六进制，位0—5见第5节；位6置1拒绝，位7以上警告但不推断扩展格式。
- 会话内元数据不可改变；相同H重发幂等。新session清空显示与序列基准，保留累计接收统计和全部记录；同一日志内旧ID不得再次使用，最多256个会话，超出须拆文件。日志若没有H不猜单位或拼接旧会话。
- W的n是1—8，末批可不足8点，不补造。seq0/evt/rpos/rr及uptime_ms是uint32；raw/filt有效值为int16，filt可NA。RAW_W/FILT_W/EVENT_E/STATUS_T分别约束W/有效filt/E/T输出。缺少CLASS_RESULT不得给已知类别。
- 同会话按模2^32推进样本及事件序号，自然回绕可经过0；向前差小于2^31计缺口，等于或超过半圈视为重复/倒退并拒绝。第一条观测不推算之前缺失数量；超过半圈的真实中断需要新会话。位置按W序号匹配，早到/晚到E均可在显示缓存内补标，不按接收时间画点。当前事件位置须注明检测器版本，不能称为精确R峰。
- E的hr未知为-1；rr=0或fs未知时必须未知，否则有效hr与60*fs/rr误差不大于0.051 bpm。cls为N/S/V/F/?，conf为0—100或-1；?只能配-1。T的hr/rr_ms可以-1，已知必须为正，fs必须与H相同；fs未知时两者须未知。T允许发送者汇总值，本版不强制其hr与rr_ms互为倒数，不能当已核对的瞬时心率。
- T三种drop分别计FIFO丢事件、源丢样、发送队列丢样，独立累计uint32或-1未知；不能填PC观察到的缺口代替。flags为NA、OK之一，或OVF/CLIP/SOURCE_DROP/TX_DROP的无重复竖线组合；NA/OK不得组合。OK仅在报告范围全部已监测时使用，不声称整个硬件健康。
- 整数不使用正号/多余前导零，小数不使用指数、NaN或Inf；未知数用规定的-1字面量。L.level为I/W/E，text按前两个逗号拆分，可有空格/逗号，不能含控制字符。K须有COMMAND_CK能力，cmd_id为uint32，status为OK/ERR/BUSY/UNKNOWN；本版不发送命令。
- 最大256字节包含LF/CRLF，超限丢到下一LF；非ASCII、控制字符、字段错误、越界、未知标签、不完整末行分别记统计，不制造样本。没有行校验，格式合法的数字损坏可能无法检测，不能以解析通过证明传输无误。
- 记录新建独立目录、raw.log原字节、samples/events/status.csv、sessions.jsonl及summary.json。未知解码值留CSV空白，raw里的0/-1不被抹除。默认数据文件总计64MiB，可配置；到限额或IO错误停止，不覆盖、不自动轮转。最终小摘要不计入数据限额，磁盘完全满时摘要也可能写不出。原始块先保存，限额中止可能出现原文比CSV多的情况，以失败原因和保留原文重放核对。
- 显示保留最近4096样本/256事件，CSV保存接收全过程；缺口断线绘制，不插值。已知fs只给名义样本时间，不证明真实墙钟采样节拍。未知scale显示码值，未知fs不生成秒刻度。演示是数学波形和指定标记，无真实滤波/分类/检测执行；FIFO和发送队列未测报-1。

运行及文件说明见[PC监视器教程](pc_monitor.md)。Windows串口只收入口见[PC监视器教程](pc_monitor.md#windows串口接收)，不发送命令、不实现PS/ADC驱动；串口适配仅完成假驱动与隐藏窗口检查，未操作实际COM端口，不替代人工使用、真实串口和板上连续运行验收。

## 14. PS合成流候选实现边界

独立ecg_stream使用本版字段、H.caps=0xD（原始波形/事件/状态），不声明滤波、分类或命令能力。当前输入为500Hz合成脉冲，默认5003点（ps-stream-2/QRS-ORIG-60；旧360Hz版本保留历史），scale=-1、filt=NA、cls/conf=?/-1；E直接读取原检测器FIFO位置/RR/序号，首RR=0时hr=-1。不能把它当作ADC/模型/精确R峰已经接入。

H启动及名义每秒重发，同一会话字段不变；不等待PC命令即执行有限输入。发送队列丢W按样本计tx_sample_drop，与FIFO事件丢弃独立，源合成段不跳样，超期则停止而不是追赶。最终T和L,END带统计；reason=completed不自动表示零丢弃，须核对全量。UART停滞时最后错误行可能无法传出，不能因没有FAIL字符串当成功。

每次重跑仍须重新配置PL、PC新建记录：固件session不是持久启动计数器，全复位后唯一性未获证明；源计数与PL位置同步也待板上验证。操作/计时器与驱动依据、保留策略及未验条件见[PS流式应用](ps_stream.md)。该候选是B10进展，不勾选B08/B10/B11整项，不覆盖原smoke通过证据。

## 15. 双向USB_UART的分流边界

电脑→Zynq只解析[ECG-IN-1](bridge_protocol.md)；Zynq→电脑的A确认也属于输入控制，与本文件H/W/E/T/L结果行分流记录。当前PC GUI仍是结果监视器，新增中转入口见[使用说明](bridge.md)，不把厂商二进制或A行喂给旧结果解析器。USB_UART同一连接同时读写，不能由两个程序分别占用。既有结果行不增加CRC，本次输入CRC不等于结果方向已受校验保护。


### 独立启动学习候选的身份

独立ecg_auto使用firmware=ps-auto-1、detector=QRS-AUTOPEAK-60，维持500Hz、caps=0xD、scale=-1、filt=NA、cls/conf=?/-1。它与QRS-ORIG-60是两个明确实现身份，不改变ECG-UART-1字段或ECG-IN-1确认。先有合法H，然后L说明WARMUP samples=1000 policy=no_events preserve_indices，最后A READY；L是说明文本，不是输入确认或新增能力位。

两秒预热不输出候选，随后3个内部时钟提交启动计算，期间原样本序号继续推进；首次RR=0仍表示未知。事件位置仍是积分窗中心近似，不能直接宣称精确R峰。电脑中转显式接受上述两个detector身份，其他未知身份仍拒绝。候选构建/操作和边界见[说明](qrs_auto.md)，准确性和是否上板以[记录](records/qrs_auto_20261021.md)为准，不能沿用原版验收。

## 分类接口结果的单发规则

内部心拍/模型合同见[ECG-CLASS-1](classification_protocol.md)。保持本版E字段和重复evt拒绝行为：检测后暂存，待分类完成、超时或确定无效后按原evt顺序只发一次E，不先发未知再重发同evt回填。未知class/conf仍为?/-1。软件参考可携带开发权重的真实分类，但必须通过L,W标明DEV_MODEL_UNACCEPTED及模型身份，不冒称最终模型或板卡来源；假后端不能声明真实CLASS_RESULT。无分类时限/INT8/硬件寄存器的暗含承诺。

## QRS26-ARM候选的输出范围

新360Hz ARM应用返回QRS26-ARM，fs=360、scale4096、caps0xD；波形为上传原值，滤波支路NA，类别?/置信度-1，状态明确NO_MODEL。分类模型未交付，不能声明CLASS_RESULT；原W/E字段与重复evt拒绝行为不变。调试L,WIN是128点float32窗口的十六进制分块，只作当前验证旁证，不作为新增分类结果报文。

接受I之前的boot H是初始化就绪，电脑送样客户端另按[输入协议](bridge_protocol.md)识别，不作为真实采样会话。原旧500Hz/AXI链路证据不继承到本候选，完整新C流程的实板证据另见[移植记录](records/system_port_20261024.md)。
