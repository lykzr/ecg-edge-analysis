## 2. 已有验收规则与数据隔离

当前[Git协议](../data/cnn_git_v1_protocol.json)的工程门槛为：macro-F1≥0.85、各类F1≥0.70、N/S/V/F召回分别≥0.95/0.80/0.80/0.70、参数≤100,000。当前CV检查覆盖各折和合并开发OOF，选型按平均折验证macro-F1、同分比较验证损失。它们是现行工程规则，不是竞赛硬指标或临床标准；不能因失败就改低后宣布原任务合格。

输入、患者角色、类别、训练采样和评分口径先冻结；201/202按同一受试者处理。参与选轮次/选结构的患者是开发数据，即使曾叫test也不能重新称未触碰测试。只有版本/预处理/阈值/拟合规则和评估方案冻结后，才按C10使用保留测试；测试结果不得反过来决定是否继续或选量化参数。

若认为任务或门槛需调整，提出理由、影响和新协议，交用户/团队明确确认；旧失败与原协议保留，本文不授权变四类为二类、不把N解释成健康、不把其他类解释成疾病诊断。范围解释见[心拍/节律与疾病记录](records/ecg_scope_20261017.md)。

## 3. 诊断顺序：先复核，再提出新假设

### 3.1 数据角色与来源覆盖

只使用当前允许的训练/开发数据。先复核逐类、逐患者、逐记录/来源数量、标签映射和分组，再查看模型混淆。v8的F拍并非不足100这一旧建议假设；真正应检查的是有效患者多样性、集中度、跨库导联/幅值/标注位置差异及少数类错误是否集中于少数人。

保留开发验证的自然类别构成，不为“每类至少5%—10%”改变评分集。不为模型难以预测而删患者、删标签或重标；疑似数据错误单独保存原始证据及修订理由，必要时另立版本，不能悄悄改旧结果。

从已知开发集按预先固定的患者/类别规则抽取典型样本和误判样本，比较原始波形、切拍/归一化张量、真实/预测类别和历史RR。困难样本图只是定位依据，不能把肉眼疑似标注问题当已确认原因；新6人测试不参与看图诊断。

### 3.2 输入流水线与设备一致性

按C05及采集A03/A06/A07核对：导联/极性、物理单位、采样率与重采样、切拍窗/边界、差分/历史RR、归一化、缺失/无效值和可用时刻。当前协议为专家位置切拍128点/144Hz，约356ms前窗、533ms后窗；这是分类器输入与等待定义，不代表自动检测链或实际设备已匹配。

对同一批允许的开发心拍，逐阶段对照训练、浮点推理及后续PS预处理输入；拟合统计仅用允许训练折。滤波/重采样/窗口变化需要新实验版本，不能假定滤波更干净就适合旧权重。裁切偏移、低幅值、极性等检查应使用可解释的对照，不以对齐标注得分为目的拟合时间偏移。

### 3.3 训练与验证行为

先读取[实际训练代码](../data/train_cnn_cv.py)和保存的配置/epoch/result文件。现有流程已经有：训练折患者/类别上限、平方根类别权重、AdamW、学习率0.001、CosineAnnealingLR、batch256、最佳验证checkpoint和早停规则。来源/增强、微调和比例校正也已有失败尝试，见第6节；不能笼统建议“先加class_weight、学习率衰减或过采样”而不指出与旧方案的差异。

现有epoch记录包含训练加权损失、验证损失、验证macro-F1及逐类指标等字段；先整理实际存在的曲线，不虚构完整训练accuracy曲线。加权训练损失与不同统计口径的验证损失不能仅凭大小差就判定过拟合。loss>2、训练accuracy<80%或batch<16没有本项目通用的容量判据。

联合检查每折训练/验证逐类表现、梯度/数值和误判来源。低训练分数可能来自实现/输入/损失或容量问题；训练好而跨患者差也可能涉及域差异，不能凭单一阈值确认原因。小批可学习性排错只有在需要且获准时做，不作为泛化成绩。

### 3.4 模型结构与部署可行性

当前小网络作固定对照。[模型计划3.5](../report/model.md#35-网络规模与zynq-7020部署选择)允许按假设适度增强，但须固定数据角色和指标，清楚区分结构、输入、训练策略变更；没有证据不能断言模型太小、7020带不动或增大一定有效。数据不足也不由“样本少于5000且12k参数”这一规则直接判定。

有开发收益的候选再核算权重/峰值激活缓存、算子和位宽、乘加/带宽/等待/推理时延，验证INT8逐类损失，再交B05做硬件数值/资源验证。100k参数是当前工程门槛，不是硬件物理上限。训练、整数参考、FPGA实现与板上运行分别验收，不能用PS浮点替代FPGA目标。

## 4. 先利用现有输出的诊断产物

建议形成一份短诊断记录，而不是预先承诺一天查明根因或几天达到质量：

| 产物 | 可以回答什么 | 注意边界 |
| --- | --- | --- |
| 逐类/患者/来源数量与混淆 | 错误是否集中于特定患者/形态，S/F覆盖是否薄弱 | 来源身份未知不能算独立新增患者；只用允许开发数据 |
| 现有训练/验证曲线与最佳轮次 | 是否收敛、何时退化、哪些类别被牺牲 | 统一指标口径；缺失字段标缺失，不补造日志 |
| 固定规则抽取的原始/处理后误判图 | 可能的幅值、导联、切拍或形态问题 | 标注是计分依据，不因模型错就删除难例 |
| 输入逐值/容差核对 | 代码路径是否一致、归一化是否越界/泄漏 | 仅证明实现一致，不证明分类质量 |
| 假设/证据/反证与下一项实验表 | 哪个改动值得验证、与旧尝试有什么不同 | 无收益记录保留，未证原因明确写待验证 |

已有三折权重、归一化和保存预测在[data/baseline](../data/baseline/README.md)。可先用标准库核对：

```powershell
python -B sim/check_training_checkout.py
python -B sim/check_baseline.py
```

NumPy环境可用sim/check_baseline.py --metrics重算保存预测的指标；按[训练交接](model_training_handoff.md)重建Git开发缓存后，Torch环境可加--cache-dir和--replay-weights重放，不重训也不读独立测试。这里是复核入口说明，不代表本轮运行或新独立成绩。

如果已有输出不足，先列缺少的字段/图和读取范围，再决定是否补诊断工具；不在未查现有verify_cnn_cv.py、结果JSON和epochs.jsonl前默认又新建一套评估脚本。

## 5. 后续实验与决策边界

- 先确认可重现的现象与数据/代码角色，再冻结一项可检验假设、参照、允许的改动、停止/选模规则及预算。
- 获得当前训练授权后才执行新训练，用已知开发患者验证；可以查明失败，也可以得出证据不足，不预先要求必须找到单一根因。
- 检查点沿用[总计划](../report/project_plan.md#共同排期与协作)，不以某天macro-F1>0.65或>0.7另设一套通过规则，也不在决策会上提前查看保留测试。
- 失败保留原协议/权重/指标，不降低门槛使原任务变合格；如果确需变更范围，单独提案、用户/团队确认并同步正式计划及报名/报告，不在本文切换二分类、取消S/F或放弃CNN/INT8/PL。
- 不预测竞赛得分、不引用无来源的“文献通常F1范围”或“临床上实际就是这五类”。对具体公开方案比较时，要提供来源/许可、患者划分、类别和同口径复现证据，不能继承论文成绩。
