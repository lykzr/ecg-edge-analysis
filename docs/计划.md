# 基于 Zynq-7020 的心电边缘分析系统方案

> 状态：方案草稿，待确认。本文不代表算法、数据或硬件已经实现或验证。

## 1. 项目定位

本项目拟实现一套运行在 Zynq-7020 上的单导联心电边缘分析原型，先完成连续采样流的实时预处理、QRS 检测、心率/RR 间期计算和信号质量提示。项目关注低资源硬件上的实时处理，以及运动/接触噪声下检测结果是否可靠。

系统定位为竞赛演示与算法验证原型，输出心电特征和异常片段提示，不作为临床诊断设备，不宣称医疗认证或疾病诊断能力。

**核心问题：**当心电波形受基线漂移、肌电和电极运动伪迹影响时，如何在 Zynq-7020 上保持实时处理，并减少低质量信号造成的错误心搏提示？

## 2. 候选技术亮点

建议把“信号质量感知”作为候选创新点，而不是只展示常规滤波和心率计算：

1. 对滑动窗口计算信号质量/噪声特征，区分可分析片段与低可信片段。
2. 根据质量状态调整 QRS 检测门限或检测策略。
3. 低质量片段明确提示“信号质量不足”，避免把不确定结果伪装成可靠心率或异常判断。
4. 比较固定门限检测与质量感知方案在多种噪声条件下的误检、漏检和延迟。

这是一项待验证的设计假设。若实验显示质量感知没有稳定改善，就应缩小或更换创新点，不把它写成既定成果。

## 3. 系统结构与软硬件分工

输入 ECG 数据 → AFE/ADC（具体型号与接口待确认）→ Zynq-7020 PL 流式处理 → PS 配置和结果管理 → PC/板端界面显示波形、检测点、心率和质量提示。

### PL（可编程逻辑）

- 接收带有效标志的定点采样数据。
- 实现基线抑制、带通滤波；工频陷波作为可配置项，是否需要由采样环境确定。
- 实现经典 QRS 检测基线，例如 Pan-Tompkins 思路的定点流式版本。
- 输出检测位置、RR 间期、质量状态和溢出/异常标志。
- 优先做可综合、可逐样本对照的流式模块，之后再决定是否加入更复杂的分类器。

### PS（处理系统）

- 配置 PL 参数，负责启动、复位、状态读取和结果缓存。
- 通过串口、网口或板端服务把波形与分析结果送到 PC 界面。
- 保存原始输入、参考标注、PL 输出和测试条件，便于复现。
- Python/Jupyter/PYNQ 可作为候选上层环境；是否采用取决于实际板卡支持情况和团队的软件基础。

### 采集前端

开发板完整型号、底板、模拟前端（AFE）、ADC 和接口尚未核实。心电电极信号不能直接接入 FPGA IO；真实人体采集阶段必须使用合适的隔离与保护型心电前端。前期优先使用公开数据回放或 ECG 模拟器验证算法，不把人体连接作为 bring-up 的第一步。

## 4. MVP 与推进阶段

| 阶段 | 目标 | 验收证据 |
| --- | --- | --- |
| A. 软件参考模型 | 读取公开数据和标注，完成浮点滤波/QRS 检测与可视化 | 可复现脚本、固定数据划分、逐记录指标 |
| B. 固定点与 RTL | 固定采样格式和定点位宽，完成滤波与 QRS 检测模块 | testbench、自检向量、与软件模型逐样本对照 |
| C. 板上数据回放 | 先用可控数字数据流把样本送过 PL/PS，输出检测结果 | 连续运行、无丢样、样本计数一致 |
| D. 质量感知 | 加入噪声/低质量判定和门限调整，比较固定策略与自适应策略 | 干净与受噪测试集上的误检/漏检变化 |
| E. 前端集成 | 确认 AFE/ADC 后接入实时采样 | 输入到结果的板上演示、接口与安全说明 |
| F. 性能与交付 | 记录资源、时序、延迟、吞吐及可测功耗；整理复现工程 | 可重建工程、版本信息、测试说明、演示材料 |

MVP 的边界是：板上能够处理连续 ECG 样本流，给出 QRS 位置、心率/RR 和信号质量状态，并能与软件参考结果对照。完整心律分类属于后续扩展，不阻塞 MVP。

## 5. 数据与验证

### 推荐的公开数据

- [MIT-BIH Arrhythmia Database](https://physionet.org/content/mitdb/1.0.0/)：包含 48 条带参考标注的心电记录，可用于 QRS 检测和心搏分析的初步验证。按记录/受试者划分开发集与测试集，避免相邻片段跨集合造成数据泄漏；遵守数据库许可和引用要求。
- [MIT-BIH Noise Stress Test Database](https://physionet.org/content/nstdb/1.0.0/)：包含基线漂移、肌电和电极运动噪声测试资料，可用于受控抗噪压力测试。其带噪心电由少数原始记录叠加噪声生成，适合检验算法在指定条件下的变化，不能单独代表全部真实佩戴人群。

### 指标

- QRS 检测灵敏度与阳性预测率。
- QRS 定位误差（样本数或毫秒）及心率平均绝对误差。
- 不同噪声类型/强度下的误检和漏检变化；低质量片段被正确标记的比例。
- PL 与软件参考模型的一致性、端到端延迟、持续吞吐率。
- LUT、FF、BRAM、DSP、时序余量；功耗只有在有明确测量方法和设备时才报告实测值。

### 对比实验

1. 软件浮点参考 vs. 软件定点模型：量化误差。
2. 软件定点模型 vs. PL 实现：功能与逐样本一致性。
3. 固定门限 QRS 基线 vs. 信号质量感知方案：干净/受噪条件下的检测指标。
4. PS 软件路径 vs. PL 流式路径：延迟、吞吐、资源和功耗（可测时）。

所有表格区分仿真/综合估算值与板上实测值；没有上板测过的内容不写成硬件实测结论。

## 6. 算法范围控制

第一版只做可解释、能逐样本核验的滤波与 QRS 检测。之后如 QRS 与数据链路已稳定，可以评估心搏类别或节律片段分类，并与简单基线比较。

LSM（液态状态机）可作为后续候选，但需先在 ECG 数据上证明精度/鲁棒性收益，并确认定点实现与 Zynq-7020 资源可行，再决定是否纳入主方案。NARMA10、Mackey–Glass 等通用时序基准或电机振动示例不能代替 ECG 数据验证。

## 7. 主要风险与待确认项

| 待确认项 | 对方案的影响 |
| --- | --- |
| 开发板完整型号、底板与启动方式 | 决定约束文件、PS 配置、可用外设与上板流程 |
| AFE、ADC 型号/位宽/采样率/数据接口 | 决定输入模块、滤波参数和实时采集路径 |
| 当前是否已有隔离式 ECG 模拟前端或 ECG 模拟器 | 决定真实采集演示的时间和安全边界 |
| 团队分组、报名赛道和提交规则 | 决定报告、源码、开源许可和演示材料范围 |
| Vivado/Vitis 版本、是否使用 PYNQ | 决定工程可复现方式与 PS 侧软件结构 |
| 演示输出方式（PC/串口/网口/显示屏） | 决定 PS 通信与界面工作量 |

## 8. 当前阶段建议

1. 确认板卡与采集前端，不先购买或假设某个 ADC。
2. 先搭建公开数据读取、QRS 参考算法和指标脚本。
3. 选定固定点格式和输入接口后，再写 RTL/testbench。
4. 数字数据流在板上跑通后，再接真实模拟采集硬件。
5. 最后用抗噪对比和硬件指标形成竞赛证据链。

比赛方向和提交约束以当届最新官方细则为准；项目仓库的目录和文件名使用英文，文档正文可使用中文。
