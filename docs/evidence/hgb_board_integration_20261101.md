## 复现要点

连接并确认实际UART身份及500Hz就绪头，不能仅凭COM编号识别设备。使用[模型接入](../model_integration.md)中的独立模型环境，先运行model/inference/check.py。合成输入按下列方式生成，再从“实时与板卡”选择标准500Hz输入，预处理选“已匹配0.5Hz因果高通→模型raw”，启用采集结束自动分析：

```python
import numpy as np
from scipy.signal import lfilter
x = np.loadtxt('model/inference/examples/synthetic500.csv', delimiter=',')[:5000]
a = 500 / (500 + 2*np.pi*0.5)
y = lfilter([a, -a], [1, -a], x, zi=[-a*x[0]])[0]
codes = np.clip(np.copysign(np.floor(np.abs(y*4096)+0.5), y), -32768, 32767).astype('<i2')
with open('tmp/board_synthetic500.csv', 'x', encoding='utf-8', newline='') as f:
    f.write('index,sample,fs,scale\n')
    for i, value in enumerate(codes):
        f.write(f'{i},{int(value)},500,4096\n')
```

第二轮取15000点、换新输出文件。在第一轮DONE且串口释放后直接开始，不下载或复位。检查完整来源/确认/回显数、逐点回显、END/DONE、模型任务和逐拍结果；不能只看界面出现波形。完整数值口径沿用固定模型协议。

## 失败与回归

首次工具预检直接比较Windows两种枚举的USB身份字符串，因大小写/分隔符格式不同在发送前中止；该轮未创建板端会话。核对同一完整实例组件并规范化比较后，另建轮次完成，原失败保留。

同步队友显示更新后，严格源码检查发现新显示模块未列入必需清单，补实际依赖与对应测试，不放宽模块检查。网页C模拟链路的一次全量回归在45秒截止时仍处于运行态，已提供6000点、确认5792点；据此确认是测试等待截止，推测高频下载完整快照增加了执行争用。测试改为30秒有界等待后台关闭，再通过HTTP核完整输出，数值条件不变；重新全量90项通过、0失败、1警告，原失败JUnit保留。新显示处理3项、呼吸滤波2项、前端波形5项均通过。

新构建脚本原先无条件删除整个缓存，导致SkipInstall同时删除所需依赖；移除该自动删除，保留队友其他更新。修复后的build/build_web.ps1 -SkipInstall实际通过TypeScript及Vite构建，49模块。没有清理原资料、历史记录或工具工作区。
