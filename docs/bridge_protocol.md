# 电脑送样与USB_UART双向协议

## 路线与协议边界

固定路线为`ADS1292R → STM32 → 蓝牙 → 电脑 → 板载USB_UART → Zynq`，Zynq经同一USB_UART返回结果。电脑保存采集原码并中转，不用电脑计算替代报名要求的ARM/FPGA对照。

| 段 | 协议及职责 |
| --- | --- |
| ADS1292R→STM32 | 芯片SPI，9字节/采样；不属于USB输入协议 |
| STM32→蓝牙→电脑 | 厂商10字节/一点或DOCX的34字节/四点；显式选版本，实际固件/蓝牙透传方式待核实 |
| 电脑→Zynq | 本文ECG-IN-1：单通道int16样本、会话、序号、CRC32及确认 |
| Zynq→电脑 | 运算/波形用既有[ECG-UART-1](uart_protocol.md)；本次输入的确认用独立A行，不混成结果E或旧命令K |

USB_UART为全双工双向连接，不是两条单工串口。A盘主目录V3.9底板图第6页的CH340C/U11/U12/P5与Vitis指南第201、205页提供双向通路依据；实物修订、P5选择和持续收发仍待验。蓝牙为用户确认的JDY18及配套USB接收器；实际串口身份/固件和帧边界仍须实测，不能由型号推定。

## ECG-IN-1约定

软件候选v1固定500Hz，与当前独立500Hz硬件匹配。只允许一次会话，源序号从0连续增长，上限1800000点；本版不做uint32回绕、缺口继续处理、运行时改率或重新初始化PL。新会话必须重新配置PL；初始化检查只能拒绝可观察残留，不能替代复位/重配。旧360Hz smoke不受影响。

所有输入及A确认：`正文*CRC\n`。正文为ASCII，CRC为8位大写十六进制CRC-32/ISO-HDLC（反射多项式0xEDB88320，初值/末异或0xFFFFFFFF，与Python binascii.crc32一致）。覆盖正文全部字节，不含星号、CRC或换行。最多256字节含LF，不接受CR、空字段、多余字段、非规范数字或前导零；会话是1—32位英文字母/数字/点/下划线/连字符。

```text
I,ECG-IN-1,<session>,500,<source>,-1*<CRC>
D,<seq0>,<n>,<sample0>,...*<CRC>
F,<total>*<CRC>
A,ECG-IN-1,<session>,<next>,<state>,<reason>*<CRC>
```

- I只负责初始化本次输入合同，不控制STM32、蓝牙或ADS1292R采样配置；source为SYNTH/REPLAY/ADC，只是来源声明，不能证明已经实采。scale本版只允许-1，表示未标定的算法int16码，不冒充mV。
- D含1—32点，值为-32768..32767。先完整校验一包再送PL，不在半包或CRC错误时提交任何样本；seq0必须等于上次确认的next。32点上限与既有结果W的1—8点不是同一个协议限制。
- 电脑采用一包在途：收到READY才能发D，收到ACCEPTED才能发送下一包；源端和结果端仍持续读取。next表示已提交PL的总样本数。确认不证明真实信号准确性、检测准确率或上板正确。
- F只在全部样本已确认后发送，total必须一致；板端输出最终T/L与DONE确认后结束。末批不补零，不以静默断连或无FAIL文字当成功。
- A.state为READY/ACCEPTED/DONE/ERROR；正常reason为NA，错误为大写标识。A是输入控制回复，结果解析器不负责解析；中转器分流并分别留原始日志。
- 本版不自动重传。坏CRC、乱序、重复包、参数不符、队列满或中途新会话立即停止该次会话；避免已经送PL的包被重复执行。保留现场，重新运行需新会话及新PL状态。
- 上位机确认超时默认2秒；板端完整会话空闲5秒、半行停顿2秒或发送无进展2秒退出并报错。任何超时都不能自动复位或声称缺失样本是0。

## 运算、序号和记录

Zynq接收缓存中的已采样数字数据按序送PL，不再生成脉冲，也不按蓝牙包到达时间推断采样时间。fs仍决定120ms积分窗60点、200ms不应期100点及RR/心率换算。它是流式处理候选，不强求将已采集样本再人为延时2ms；实际延迟和吞吐在板上另测。

结果H使用同一个session，source沿用I，detector=QRS-ORIG-60、fs=500、scale=-1、caps=0xD。W回传实际提交PL的int16样本，E保持PL原始序号/位置/RR，T.source_sample_drop=-1（无法证明上游没丢样），无滤波/分类，分别为NA与?/-1。ECG-UART-1结果行仍无CRC；不能把输入CRC或A确认扩展成整条链路无误码的保证。

厂商数据的电脑接收编号不是ADC源序号。电脑保留完整二进制原文及CH1/CH2的24位有符号码；选定通道和位移后生成算法输入，位移按算术右移、超int16饱和，单独计削顶。channel/shift必须显式指定，不宣称标定合格。来源标识、原码编号与输入序号的映射保留在记录中；中途损坏或失去边界停止，不能删坏点后压紧编号继续。

## 负载与验证边界

使用原板载UART0，115200/8N1/无硬件流控；收发通过独立队列和确认解耦。满宽int16、原始W回传、A与事件/状态会消耗带宽；一包在途不是无限吞吐保证。采集连接必须持续排空，有界缓存满即失败留证，不静默丢弃或暂停显示冒充采集未丢样。蓝牙/USB驱动、500Hz持续吞吐、拔插和实际PL事件都必须上板验收。

对应程序为独立ecg_bridge，保留ecg_stream合成回归与smoke；[中转使用说明](bridge.md)给出入口和边界。旧500Hz有限合成/双向数字回放已上板，冻结360Hz ARM另有数字回放证据；真实无线/物理拔插与新QRS原生500Hz仍待验。

## 冻结360Hz ARM候选的显式输入合同

独立ecg_runtime接受I,ECG-IN-1,<session>,360,<REPLAY或SYNTH>,4096及原CRC，源样本必须已经是4096单位/mV的int16。D/F/A语法不变，原旧500Hz/-1合同仍是ecg_bridge默认值。电脑明确选择runtime360 profile，只接受QRS26-ARM/360/4096/0xD，不自动猜测或换算两种合同。

新应用在接受I前周期发送合法的ECG-UART-1启动H：firmware=ps-runtime-ready、session=boot、source=UNKNOWN、detector=QRS26-ARM、fs360、scale4096、caps0xD。它表示算法初始化就绪，不含样本；客户端仅在runtime360未启动状态识别后发送I，旁证保留到controls/usb_rx，不混入正式results采样会话。新的I得到电脑session对应的正常H和READY后才送D。旧500Hz客户机不接受该身份，不改变默认语义。

真实500Hz厂商数据仍不得送此合同；不采用失败500Hz转换候选。操作与ARM/PL分工见[板端运行](runtime_board.md)。

输入码值、序号与缺口合同统一见[输入合同](input_contract.md)；当前往返计时字段见[性能测量](performance.md)，不等同板端纯计算。

## 新500Hz标准数字输入

独立ecg_runtime500使用相同D/F/A语法，显式I声明500/4096、来源REPLAY或SYNTH；profile=runtime500，启动身份ps-runtime500-ready、detector=QRS26-500-ARM，正式会话firmware=ps-runtime500-1。W、E位置、RR和fs均使用500Hz源时轴，内部转换不改变源编号。标准500和旧厂商500/-1是不同合同，不能自动互换。细节见[500Hz说明](rate500.md)；已知构造数据的软件等效不代替真实采集/无线验收。
