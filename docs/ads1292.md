## 已核对的输入格式

### 已取得的连接信息

- 用户补充确认：采集设备到电脑使用USB蓝牙传输模块，无线传输；采集数据可以导出CSV。无线指采集侧至电脑这一段，电脑至Zynq仍按既定USB_UART路线。实际CSV列、软件时间轴和滤波关系已核对，见下节；物理标定和硬件节拍未实测。
- **用户已确认实际发送每帧34字节**，接入选择现有`document_34`分支，按资料定义解码`AA BB + 4×(CH1四字节+CH2四字节)`。这是用户确认的帧长，尚未收到原始抓包核对字段、边界和连续收流；10字节保留为配套源码的另一版本，不自动切换或猜测。
- 用户确认蓝牙模块型号为**JDY-18**。用户提供的《ADS1292R-STM32使用教程》正文及图片说明，电脑端使用配套USB接收适配器，并要求CH340串口驱动；不据此认定电脑自带蓝牙能直接生成串口。教程称收发两端蓝牙状态灯常亮表示连接成功，实物仍需验证。
- 用户截图中的上位机标题为“ADS1292R 心电呼吸监测系统 v2.1.2”，串口设置显示**115200**，支持CSV/TXT记录。截图底部为“已断开连接”，现有波形不能作为实时收流或采集验收通过证据；纵轴标注ADC，不能把码值直接标成mV；卖家参数已确认后可按下节做标称换算，仍未实测标定。也不能仅据上下图名称确定CH1/CH2映射。
- **采集COM号会变化，不固定为COM4。** COM4仅为此次截图值。按用户要求，后续连接时应枚举当前串口，结合USB设备身份、插拔变化和已确认的数据格式区分采集适配器与Zynq USB_UART；描述/VID/PID相同或证据不足时不能唯一认定端口，应提示选择，不能盲目打开所有端口或发送探测命令。当前CLI仍要求显式指定端口，自动识别尚未实现。
- 上位机已明确CH2心电/CH1呼吸及34字节解析，不再把软件映射列为未知。待补实际完整固件版本及原始二进制抓包，核对实物匹配和边界；实际采样率、实测标定与24→16位策略仍待核实；卖家已确认标称参考电压2.42V、PGA增益6，依据与边界见下节。源码配置500SPS不等于本次实测，CSV不直接证明串口传输无丢样。
- 用户提供过连接账号/密码，其用途尚未由教程说明；此处不保存明文，也不据此推定蓝牙配对方式。串口设置115200与ADC采样率是不同参数。

### 上位机与CSV的软件定义

目录内上位机没有单独源码文件，现已静态读取其Python 3.11打包字节码，未运行EXE。内部config的APP_INFO标注v2.1.2，与截图版本一致；版本号一致不单独证明其他电脑运行的是相同构建。源文件SHA、函数位置和CSV核对见[详细补记](records/ads1292_20261019.md#2026-10-20补充-上位机与真实导出文件核对)。

| 项目 | 当前已核查的软件行为 |
| --- | --- |
| 解析 | FRAME_LENGTH=34、SAMPLES_PER_FRAME=4，AA BB后四组CH1/CH2各四字节大端；波特率115200，SAMPLE_RATE=500 |
| 通道 | SerialWorker发出CH1/CH2及两路滤波值，MainWindow将CH1存为resp_raw、CH2存为ecg_raw |
| 编码 | CSV原始列保留偏移码；计算/显示前减8388608，滤波列已是处理后的浮点码值，不能再次减偏移 |
| 心电滤波 | CH2减偏移后经过0.5～40.5Hz带通，四个二阶节；该支路没有另外串联50Hz陷波 |
| 呼吸滤波 | CH1减偏移后经过50Hz陷波，再经过0.1～0.5Hz带通 |
| 时间 | RawData由累计点数÷500生成；HeatData每写一行内部时间加1秒，均不是ADC源时间戳 |
| 参数摘要 | 心率与ECG间期独立计算；间期检测无合格周期时保持上次结果，有合格周期时取最近最多五个周期的中位数。摘要不是逐拍标注，也未验证临床准确性 |

现有客户端已增加独立采集视图，可读取五列厂商RawData CSV、按CH2心电/CH1呼吸预览，并接入34字节采集串口；使用入口见[PC采集操作](pc_monitor.md#采集与厂商csv)。这部分只有软件/隐藏窗口和假串口检查，真实蓝牙采集仍待验。原中转CLI仍只支持已转换int16的sample列CSV或显式配置的厂商二进制，GUI双向送样尚未接入。总体方案见[主体计划2.8](../report/system.md#28-把采集功能接入现有客户端的方案)。不复制打包代码/滤波系数、登录或联网认证，不把厂商滤波CSV冒充Zynq已实现滤波。

### 标称电压换算

参数来源为用户在2026-10-21提供的卖家聊天截图：用户询问是否采用2.42V内部参考和PGA增益6，卖家明确回复“是的”。按这两个标称参数，可将心电通道24位有符号码C换算为ADS1292R输入端差分电压：

`V_mV ≈ C × 2.42 × 1000 / [6 × (2^23 − 1)]`

本版厂商CSV的ecg_raw先按C=ecg_raw−8388608恢复有符号码；已经解码的有符号码或滤波列不能再次减偏移。约每码48.08nV，理想差分满量程约±403.3mV；用户换算截图末行的±403.3μV有1000倍单位错误。截图公式使用2^23是近似，严格口径见[TI手册8.3.8](https://www.ti.com/lit/ds/symlink/ads1292r.pdf)；输入范围见手册8.3.4。

这里记录的是卖家标称参数与理论换算，没有实机寄存器读回或标定结果，不能把1LSB步长当作测量精度。实际供电/共模等输入条件仍按原手册核查。本次归信息采集A03，不据此修改QRS/CNN、34字节厂商帧、ECG-IN-1/ECG-UART-1或既有24→16位程序。需要mV显示/导出时保留原码、参数来源和换算结果，具体实现仍列在[采集计划1.9](../report/capture.md#19-adc电压换算的卖家确认)。

### 芯片SPI

手册第11页规定CPOL=0、CPHA=1（SPI模式1），第42页规定每点9字节：3字节状态、3字节CH1、3字节CH2，均高字节在前。通道是24位二进制补码，范围-8388608至8388607；状态为`1100 + LOFF_STAT[4:0] + GPIO[1:0] + 13个0`。

`decode_spi_frame`检查帧长、固定前缀和保留位，提取状态字段与两个有符号码。调用者须先依据DRDY/CS划定一帧；本函数不从任意字节流猜测边界。LOFF字段保留原始值，其含义还依赖寄存器使能及实测，不能直接当作已经验证的电极脱落告警。

### 附带STM32串口/USB

两种格式的通道均占4字节、大端、高8位为0；低24位是原始补码异或`0x800000`所得的偏移码。恢复有符号值应减`0x800000`，不能当32位有符号数直接读取。

| 解码参数format | 来源 | 帧长/采样点数 |
| --- | --- | --- |
| source_10 | 实际USER/main.c的USARTx_Send(...,10)，USB循环同样发10字节 | AA BB + 1×(CH1四字节+CH2四字节)，10字节 |
| document_34 | 附带协议说明的四点合包版本 | AA BB + 4×(CH1四字节+CH2四字节)，34字节 |

`decode_vendor_frame`必须显式指定版本，返回按时间排列的`((ch1,ch2),...)`。本模块只接收完整且已划界的帧，拒绝残帧、拼帧、错误帧头及非零高8位。数据内部也可能出现AA BB，两个协议均无CRC和样本序号；因此不实现看似可靠的自动识别或丢字节重同步。实际固件是哪版，需要配置来源和抓包验证，不能由目录名推定。

## 例程存在的冲突和接入条件

1. **采样率**：ADS1292.H选择500SPS，手册第52页DR=010在规定主时钟下对应500SPS；这只是代码配置，实际DRDY节拍待测。芯片标准速率表没有360SPS。当前独立PS/PL合成流候选已按用户要求改为500Hz，旧smoke仍为360Hz；前者还未上板。真实前端的DRDY节拍仍须测量，滤波/切拍/模型输入的采样率适配仍需单独验证，不能只改会话fs。
2. **通道用途**：头文件前面说CH1为ECG、CH2为呼吸，RLD段又写ECG为CH2。2026-10-20已由上位机实际赋值确认本版软件CH2心电、CH1呼吸；呼吸调制/解调作用于CH1，与此一致。不再沿用相反注释，但实际固件/接线版本、导联、极性与物理标定仍需核对。
3. **相位注释错误**：源码RESP_PH=0x02、FREQ_32K；第60页表26对应22.5°，不是注释的67.5°。不采信注释中“已修复尖峰/串扰最小”等未经本工程验证的结论，也不据此擅改寄存器。
4. **供电与电平**：原理图P1标5V、电源含MIC5219-3.3，源码却写5V脚接3.3V；两者不能合并成接线结论。TXB0108是电平转换器，不能因存在B0303S电源模块就宣称整机已电气隔离。接Zynq前需核实实物版本、电源轨、数字侧电平和地。图中文字有部分字体缺失，已交叉查看文字提取及页面，仍不把不清楚的电源连线推断成实测事实。
5. **输入范围**：手册第7/24页的理想差分满量程是±VREF/Gain；按代码所选2.42V、增益6计算约±403.3mV，还受共模和供电条件限制。这不是允许电极端输入5V、可用量程或安全限幅承诺，也不代表模块已具备人体连接条件。
6. **时序与丢样风险**：SPI寄存器读写与转换数据读取的时钟限制不同，需按第11、41、49页核查实际时钟、命令解码和CS保持。例程用单份中断缓存/单bit标志交主循环、串口逐字节等待发送；存在覆盖/竞争风险，尚无实测丢样结论。现有厂商帧没有状态、源序号、丢样统计或校验，PC收得连续也不能证明ADC没丢点。

## 本工程离线使用

仅需Python标准库，从项目根目录执行：

```powershell
python -B -m unittest discover -s sim -p test_ads1292.py -v
```

解码接口位于[src/reference/ads1292.py](../src/reference/ads1292.py)：

```python
from ads1292 import decode_spi_frame, decode_vendor_frame
sample = decode_spi_frame(bytes.fromhex('c00000 800000 7fffff'))
points = decode_vendor_frame(bytes.fromhex('aabb 00800000 00000000'),
                             format='source_10')
```

导入前将`src/reference`加入调用程序的模块路径，测试脚本已有示例。此解码模块不打开串口、不驱动SPI、不发送命令、不做QRS/CNN，也不默认选择通道、换算mV、截断为int16或自动变更采样率。PC结果视图仍只收ECG-UART-1；新增采集视图单独处理厂商34字节，并明确标注三帧起始候选与无校验限制，不和结果协议混用。独立中转CLI仍要求显式确认边界/格式，见[中转说明](bridge.md)；实际固件、真实蓝牙及单位仍待核实。

## 下一步交接

先取得实物型号/接口照片、固件版本及一段原始二进制抓包；路线已确定为STM32→蓝牙→电脑→USB_UART→Zynq；继续冻结A03/A07的通道、实际采样率、码值缩放/饱和、状态与丢样合同。然后实现读出和适配，数字输入验收后再推进真实前端。

**独立PS流式程序仍只有主机检查和ELF构建证据，尚未上板验证；已通过的smoke不能代替它。** 本文和解码测试也不构成AFE/ADC、人体输入或PC实串口验收。

采集厂商帧与电脑送样协议分开；[ECG-IN-1](bridge_protocol.md)不替代本文10/34字节版本核查。
