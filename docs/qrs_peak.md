# 心跳候选的原波形确认

这部分接在原检测器之后：先产生可能的心跳位置，再查看附近原始心电，选择明显的波形极值，并检查局部变化是否比周围背景更集中。连续波形仍逐点输入，输出是心拍位置和RR，不进行CNN分类。

## 当前接口

src/reference/ecg_peak.py的PeakDetector(rate=360或500)使用既有AutoDetector产生候选。每次push(int16样本)返回零个或多个PeakEvent，包含emitted（到第几个输入点才能确认）、position（原波形位置）、rr（相邻接受事件的样本间隔）和candidate（确认前的位置）。首RR为0表示未知，不换算为有效心率。

原始序号从0开始；暂停valid=False不推进样本，reset_n=False清空启动/滤波/候选/历史。前两秒沿用原检测器启动学习；确认阶段等上下文完整再输出，不读未来、不在文件结束时补零或冲刷出未确认事件。原始数据保存与本算法相互独立，不能为展示把样本删掉或压紧时间。

## 固定处理规则

- 原波形定位半径100ms；基线使用中心±150ms中排除±80ms的样本中位数，不依据专家标注调整偏移。
- 40Hz低通只用于计算质量变化量，不修改送入核心的样本，也不冒充已经部署的ECG滤波支路。低通参考复用ecg_filter_reference.py，当前包含浮点状态。
- 比较中心±80ms与周围±240ms的平均变化量；局部变化低于背景时拒绝。400ms内再结合相对斜率、双相性和幅值检查宽波，沿用既有软件v4的参数和救援条件；200ms不应期保留。
- 环形缓冲1024点、候选队列上限16。越界或溢出直接报错，不丢掉失败输入后继续声称通过。

额外等待为100ms定位半径加240ms背景半径，均从候选位置计；由于原波形位置也在定位窗口内，理论确认等待上界约440ms。它是算法需要的样本上下文，不是ARM/FPGA执行耗时或整机延迟实测。逐记录实际样本等待在评估输出中记录，最终整机门槛仍待确认。

## 使用边界

当前是独立软件研究候选，没有接入PS流式应用、PC显示或对应RTL。原ecg_auto/bit/XSA/ELF和已验release保持原样，不能把它们的仿真/时序结果算给本模块。既有成熟GQRS/v4软件参考也保留，不因简单核心的改善就认定最终要替换它。

相关失败方案与当前结果集中[本轮记录](records/qrs_peak_20261021.md)。整体算法尚未满足原门槛时，不为新候选发布镜像或改写上板通过状态。
