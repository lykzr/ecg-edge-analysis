# 500Hz运行时QSPI固化与交接

用户授权写Flash、整理、形成交接并本地提交Git；不推送。板卡为此前唯一领航者V2 Zynq-7020，Digilent 210512180081、USB_UART COM14的USB身份与前次一致。工具为AMD 2026.1，Windows PowerShell；未改PS7/MIO/供电配置，未恢复模型训练或QRS调参。

## 镜像、编程与启动分别核验

应用构建ID a570b308ef7b46fe，正常500Hz、无完整窗口跟踪。匹配FSBL→bit→应用，BOOT.BIN为4265108字节，SHA256为d71ceed2104ca113cbc1759f5162d4a65bb8e44108b3649e7b20808ba1bd87cc。完整输入字节和SHA、原始证据的哈希见[data/results/qspi_20261025.json](../../data/results/qspi_20261025.json)。

从可写工程目录执行program_flash，指定唯一目标、qspi-x4-single、offset0、-verify；w25q256为32MiB，实际擦除0x420000字节，日志分别出现Flash Operation Successful与Verify Operation successful。没有整片擦除，也未做整片读回备份；历史Hello World镜像不是原厂Flash备份。原始日志见[qspi_20261025/program_flash.log](qspi_20261025/program_flash.log)。

第一次用户切换QSPI并上电后，BOOT_MODE仍为0，未收到就绪，未算通过。请求拔除所有USB/供电线等5秒；用户确认彻底断电重接后，读取F800025C为1，USB_UART收到新应用会话头和就绪。期间没有下载ELF、重配PL或执行PS初始化。证据见[启动模式](qspi_20261025/boot_mode.log)、[启动UART](qspi_20261025/cold_uart.log)。初次失败与完整采集保留tmp/flash_handoff_20261025，不抹去原失败。

在实际Flash启动的应用上回放已有厂商CSV：10412点发送、确认和回显均完整，26事件、0削顶，与同源C事件及归一化SHA一致。没有真实采集器，也没有逐拍标注，不报告无线或检测准确率。精选[回放UART](qspi_20261025/replay_uart.log)，CSV及主机输出留tmp。随后只执行QSPI系统复位，不下载镜像，再次就绪：[复位](qspi_20261025/reset.log)、[UART](qspi_20261025/reset_uart.log)。板卡目前等待下一轮输入，串口已释放。

## 工程修改与交付范围

新增board/prepare_qspi.py，仅用当前发布的匹配FSBL/bit/ELF就能重新生成镜像，不依赖原作者tmp；用正式入口重打包与实际写入镜像逐字节相同。新增package_qspi.py生成候选，qspi/内复用runtime500的bit/ELF，不重复复制；旧latest在history按原字节归档。没有把全套Vivado/Vitis缓存放Git。

新增QSPI默认只检查的PowerShell入口、只读唯一身份/模式探测与只复位脚本。实际写Flash采用本轮AMD命令行；包装入口仅做软件检查/篡改拒绝，不把它说成另一次实板编程。下载教程、系统计划、交接、依赖和精确ignore同步。report/交接.md按用户指定名称保留，列明所有主要未完成项；根README、资料索引与模型基线原样。

新客户端厂商去直流/标称换算的完整逐拍准确率回归尚未纳入原42条成绩。当前QRS105风险、真实无线/实际采样标定/物理拔插长时运行、新厂商界面人工验收、最终模型/INT8/完整PL及同性能比较均待办，不能把本次Flash成功写成整机完成。Git从提交克隆验证与最终检查结果在lykzr.md本轮追加。

包装入口检查首次失败是PowerShell把0xaa995566当成有符号整数，误拒绝正确镜像；修为显式UInt32转换，另补短头长度检查。失败候选保留tmp，修复后默认检查、启动镜像篡改及应用组成篡改拒绝均通过。未改变已写Flash中的镜像。
