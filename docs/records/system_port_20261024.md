# 冻结360Hz QRS、切拍和USB_UART的C移植

## 目标、范围和环境

2026-10-24用户要求继续三项任务：分类接口、完整软件流程搬到板端、通信显示联调。按当前规则保留QRS暂停与失败、模型由队友交付、Git暂停、根README/资料索引/冻结基线保护。用户确认真实ECG采集设备当前没有，因此本轮实物范围是同一领航者V2/Zynq-7020的USB_UART数字输入，不声称真实无线/人体/500Hz通过。

Windows11、Python3.14.7，原QRS依赖环境；已有MinGW GCC、Vivado/Vitis2026.1。未安装、训练、访问独立6人、修改Flash/PS7/MIO/DDR/供电。唯一JTAG-HS1 210512180081、xc7z020/ARM #0，USB VID_1A86&PID_7523\6&1ef5fd6f&0&2 当前COM23。每次实际下载前核匹配硬件/源码SHA和唯一目标，串口按USB实例核对。

## 实现和取舍

新增src/ps/ecg_runtime：逐段移植冻结research26及其GQRS/形态/模板/梯度辅助/72点确认等待，使用相同原规则/阈值/参数。GQRS平滑/能量int64，滤波/形态double，网络窗口float32；关闭浮点融合，不是INT8或PL。固定采样4096、滤波1024、峰64、模板8、待确认/切拍32、RR历史401，静态192KiB预留及128KiB应用栈。原Python参考未改。

pipeline.c按原自动位置切原波形，使用保存的101系数作360→144多相窗口变换（不是失败的500→360整流转换），恢复mV、每拍去均值/std_floor0.05mV、128点及RR3。启动/尾部不足明确WINDOW_INCOMPLETE，首RR未知，缺口拒绝、会话重建。分类核心实际串联，但最终模型未交付，应用不声明CLASS_RESULT，E类别?/置信度-1，并输出NO_MODEL/MISSING_RR等状态。当前应用RR均值0/std1只是无模型占位；有效分类前须绑定最终权重对应参数和SHA。

link.c是独立360Hz/4096单位ECG-IN-1合同；旧500Hz/scale未知的ecg_bridge源码和PC默认行为保留。PC BridgeClient显式profile区分，不能把厂商34字节或右移8的500Hz码直接送此应用。新RuntimeWorker是界面实际后台，显示子窗口增加360Hz标准CSV入口，坐标使用实际采样率；电脑只发送/记录/显示，不替板卡运行检测。

## 失败、定位和修复

1. 首次受限Vitis启动只输出头，未创建工作区；停止本次进程后在授权工具环境运行本地服务，正常构建。未结束别人的程序。
2. 第一实际ARM链接缺libm（sqrt/cos/sin/floor）；模板默认8KiB堆/栈也不足。改为显式libm、静态算法缓存、128KiB应用栈和O2/关闭融合，新工作区重建；旧失败工程和build_02.log保留。
3. 第一次上板未返回READY。保存现场后读CPU PC落在_exit，ecg_bridge_result=-7，UART ISR=0x27，确认接收溢出。新内核初始化期间首个I行超过FIFO承载是定位到的启动竞态；增加初始化完成后的合法boot H握手，电脑收到后才发I。仅启动时清锁存接收错误，运行中新错误继续停止；主机加入未就绪不得上传测试。新版100/105实板及错误验收通过。
4. 初版主机故障测试把L,W日志中的W,当波形，改为按整行起始判断；初版隐藏Tk测试缺src导入路径、对未映射1px画布误断言有绘图项，均保留失败。改为核真实Tk状态路径，不冒称看过实际视觉。
5. 标准CSV后台的末尾短批次先标EOF再add会出错，在上板后台验证前修复；补105点短批次、500Hz误入拒绝、断连保存、停止/新会话和隐藏Tk测试。

## 实际核验

- C主机完整42条已查看记录：96931事件的emitted/position/RR与冻结360Hz逐项一致；重新计分保留TP96777/FN133/FP154及原41/42、105失败。不是新患者测试或算法质量改善。
- C/Python管线受控正负脉冲、宽波/双相、零/DC、满幅/固定种子噪声、缺口/复位和停流有针对性测试；C真实链路和界面后台也有测试。最终回归8模块99项通过，隐藏Tk是逻辑检查，不等于人工视觉。
- 100号30秒实际USB_UART→ARM完整QRS/窗口→PC：10800点上传/确认/回传，35事件和35窗口一致，最大绝对误差0；END/DONE、零残行、无已知丢弃。约30.14秒包含采样节拍和传输，不能当纯计算耗时。
- 105号120秒使用界面真实后台类RuntimeWorker：43200点全部确认/回传/保存，165事件与冻结前缀一致；源和结果快照各保留4096点，完整记录独立保存。没有实际接入第二采集串口，不能冒称双USB或无线通过。
- 三个实际故障均以新JTAG会话验收：坏CRC约0.010秒、半帧约2.010秒、停流约4.989秒返回明确ERROR，accepted=0且无W/E。不是物理拔线测试。
- 故障后再次JTAG重建会话，100号3秒：1080点/2事件/2窗口一致、最大窗口绝对误差0；未跨故障保留RR，也未自动重传旧输入。
