## 实现与取舍

- 固定现有360Hz/120ms/200ms寄存器配置，输入为先100零、后每360点一个±20000交替脉冲。默认3603点，包括3点末批。SYNTH/scale=-1/filt=NA/cls=?明确无采集/标定/滤波/CNN结果。
- 使用BSP当前xiltimer.h导出的XTime_GetTime，全局计数频率来自当前BSP。只使能计数，拒绝非零预分频，不清零、不改PS7/DDR/MIO/时钟配置，也不调用可能重启计时器的sleep。
- 相对起点按floor((i+1)*timer_hz/360)排期，每轮只送一个到期样本。错过完整名义周期时停止，不追赶突发或压紧序号。入口观测迟到ticks不冒称真实MMIO写入抖动。
- 唯一消费者读完整FIFO队首、成功排队后才弹出；不以位置/序号0判空。8KiB字节环形队列、整行原子入队，W预留1KiB控制余量；慢发送丢整批W按样本计数，事件/控制队列失败则停采。发送每轮至多32就绪字节，不用printf与协议混写。
- H启动/名义每秒重发；T三种丢弃分别表示FIFO事件、合成源段、发送队列样本。没有质量监测时不报OK；T不缓存旧心率，E由真实FIFO的RR计算瞬时心率。当前T会报未知，持续心率显示/过期策略仍需B11结合PC联调，不在此宣称已完善。
- 无命令接收，不置COMMAND_CK；有限输入结束后观察至少1ms再发末批，软件队列排空后发最终T/END，再有界等待物理UART空闲。UART停滞可能没有最后完整错误行，不能以未见FAIL认定通过。
- session为随机构建ID+启动计数，不是持久启动计数器；每次复位必须PC新建记录并重新配置PL。没有样本计数读取寄存器，启动寄存器检查不能证明曾经只写过零的旧PL未被使用；新运行配置的Program Device/系统复位仍是必要前提。

## 主机证据

既有MinGW GCC编译实际stream.c，使用C11/O2/Wall/Wextra/Werror；假计数器1000003Hz、轮询步长100ticks，假UART和假FIFO。Python既有环境3.14.7，现有PC解析器按7字节分块检查。8项unittest涵盖9种输入模式；单独保留的场景输出/解析摘要见[results.json](../../tmp/ps_stream_validation_20261018_03/results.json)。

| 场景 | 实际主机结果 | 含义 |
| --- | --- | --- |
| 正常 | 提交/接收3603样本、10事件、发送丢弃0，完成；峰值144字节，最大入口迟到99ticks | 测试时钟与假外设；不是板上性能 |
| 慢发送 | 提交3603、发送丢弃971、接收2632、事件10；最终T正确报TX_DROP，峰值7251字节 | 成功结束不等于零丢弃；源样本没有压紧编号 |
| 短输入 | 3样本、无事件、无补点 | 末批不足8点正确 |
| 调度过期 | 20样本后报SAMPLE_DEADLINE_MISSED并失败 | 无追赶发送 |
| 非新PL/配置错误 | 0样本，分别NEED_FRESH_PL/CONFIG_MISMATCH | 主机注入的拒绝路径 |
| UART完全停滞 | 720样本/2事件后失败UART_STALLED | 无线端输出，错误由主机状态确认 |
| 零值事件 | 200样本，事件seq=0/pos=0仍完整读后弹出1次 | 不把0误当空FIFO |
| 非法合同 | 非法session/频率/数量拒绝 | 不开始送样 |

假FIFO只提供已知事件，不执行QRS算法，不把主机位置79等当作新检测器或真实AXI通过。正常/慢发送的源生成值和每次送样截止也由C断言核对；PC解析无坏行/超长/残行，重复H幂等，不重建会话。

## 失败、修正与保留

1. 首轮8项测试有2个断言失败：PC本来就对相同H幂等计数，不能以H计数必须增长检验线上重发，改查原字节次数；最初慢速参数仍不足以填满队列，改成每1000ticks一个字节。另明确末尾丢批可能不可由PC序号缺口直接观察，完整性要结合最终总量/丢弃数。修正后8项通过，未改PC解析规则或降低功能门槛。
2. 沙箱内Vitis服务器因`Unable to establish loopback connection / Permission denied: connect`启动失败；Python客户端等待serverPort表现为不返回。终止本次启动后，获工具批准在沙箱外运行构建，未改网络配置/ACL。首次获准构建失败于`xtime_l.h`未导出；核对新生成的xiltimer头文件和globaltimer_sleep_zynq.c后改为当前接口。
3. 尝试移动已失败工作区时，Move-Item有部分日志因占用未能移动；命令曾继续输出ARCHIVED，**该文字不表示完整归档成功**。实际保留在tmp/history/ps_stream_20261018_failed_01与tmp/ecg_stream两处，未删除或强行移动残留。随后重试被“工作区已存在”保护拒绝，改在全新tmp/ecg_stream_retry_02构建成功。不声称失败工程仍能按原位置直接运行。
4. 保存主机证据时GCC默认系统TEMP写入失败，获准沙箱外重试仍失败；未改权限，改为子进程TMP/TEMP指向项目独立目录后成功。Python TemporaryDirectory还出现拒绝访问且自动清理失败，测试改成保留UUID目录和编译日志，不删除/重设权限。失败目录validation_01/_02和ps_stream_tests中残留保留；最终8项测试通过，完整场景证据在validation_03。
5. 成功BSP构建出现CMake长路径警告、原厂FSBL的有/无符号比较警告，实际应用编译链接成功；不把有警告说成全零警告。自有主机C核心在Werror下通过。
