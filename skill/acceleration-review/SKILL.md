# 公平计时与硬件优化取舍

适用：有软件基线、FPGA 实现和逐任务计时的推理、滤波、图像或控制项目；需要向评委/同事说明加速是否真实。通用流程不依赖 Zynq、心电、神经网络或本项目协议。

## 工作流

1. 先填 [实验合同模板](assets/experiment.md)，固定输入/模型/精度、复位与会话边界、计时阶段、参考容差和资源预算。
2. 核查“同一功能、同一输入、同一精度”。记录平台、时钟、编译选项与预热；不同平台也可比较，但不能称同器件比较。不改慢软件基线来制造加速。
3. 运行数值核对后再解释时间。浮点/定点容差预先冻结，逐拍类别、分数、状态及未分类保留。相同错误可同时出现在两侧，数值一致性不能代替专家真值。
4. 计时区分纯核、主机调用含片内传输、完整端到端。累计倍率为总基线时间/总加速时间，不对逐任务倍率做算术平均。顺序执行两种实现作比较不等于并行吞吐测试。
5. 一次只改变一个明确结构假设，保存失败版本。看层级资源定位 ROM 复制、端口数、流水线与并行度；在资源/时序/数值都可接受时再保留候选。

## 可执行计时汇总

复制整个本子目录，Python 3.10+ 无第三方依赖。输入 CSV 每行是一对已匹配任务：

```csv
sample_id,reference_ticks,accelerator_ticks,output_match
case_0,1000,250,1
case_1,2000,400,1
```

`metadata.json` 需包含相同任务定义的来源哈希、精度和计时范围；不能把两种精度日志合成一个比较。哈希、match 值由采集/核对程序提供，本脚本不重新运行模型。

```json
{
  "input_sha256": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
  "model_sha256": "bbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbb",
  "precision": "fp32",
  "reference_label": "board_arm",
  "accelerator_label": "board_pl",
  "reference_timer_hz": 1000000,
  "accelerator_timer_hz": 1000000,
  "scope": "network_and_register_transfer"
}
```

上面为合成示意，实际使用须填真实哈希/平台/频率，不可作为实测证据。脚本允许两侧不同计时频率，并分别换算秒。

```text
python scripts/summarize_pairs.py --pairs paired.csv --metadata metadata.json
```

输出总时间、均值、任务数、不一致数、输入文件哈希与累计倍率。任意不一致会退出 1、speedup=null，保留时间供排障；0 时长、重复任务、空数据、缺字段及非法计时均拒绝。不访问硬件、不发送消息、不停服务。

## 可交给大模型的提示词模板

以下为根据真实工程纠错整理的**复用模板**，不是历史对话原文；没有声称模板经过跨模型稳定性实验。

> 请根据以下算法、时钟、数据接口和资源预算提出软硬件划分。分清预处理/状态管理/核心计算/搬运。先列出需要冻结的数值和时序合同，再提出一个可证伪的瓶颈假设。给出最小改动、黄金参考、仿真/板测方案和停止条件。不能用 HLS 周期替代板上延迟，不重训、不换权重。输入材料：[源码与预算]。

> 请读取这两版原始综合/实现报告和相同输入的计时日志。先核对版本、模型/输入哈希、精度、计时范围、时钟及约束缺失，再计算总时间比值与资源变化。解释存储复制、DSP/查表实现与并行度的代价。输出支持/不支持该优化的证据，缺项明确写待验；不能用位宽同时变化的实验单独证明量化收益。

> 新旧实现出现首个数值差异。请按输入解码→预处理状态→切窗→量化/饱和→累加顺序→缩放定位，不拟合偏移、不删异常拍、不调宽容差掩盖差异。给出最小复现、失败位置和修复后必须重跑的集合。[附日志/输入合同]。

## 来源与已验证效果

本项目 FP32 全连接四输出并行后同精度含片内传输加速约 2.985→4.174 倍；INT8 卷积十六路/全连接四路及 LUTRAM 后约 5.624→9.015 倍，整系统 BRAM36 等效 130.5→122.5。过程中观察过 ROM 复制占用上升，量化前后仍有类别变化，因此保留“精度改变”和“结构优化”的不同实验口径。

这些数字仅为来源案例，不是换题目必然得到的结果。汇总脚本已核对不同频率、累计比值、重复任务和输出不一致等用例，并从既有合成流式板测逐拍 ticks 复算 72 拍约 9.020 倍，另按整段聚合 ticks 核对约 9.015 倍。见 [包级验证](../validation.json)。本轮没有新板测或重训。

## 失效条件

脚本信任计时频率、范围、match 及哈希声明；伪造/错误元数据不能自动识别。不同输入、错误任务配对、计时器溢出未展开、DVFS/中断影响、只挑好结果、未剔除声明预热会使结论无效。吞吐、功耗与完整系统延迟必须独立测量；合成演示不代表真实分类准确率。INT8/FP32 可另作跨精度对比，但不能混入本脚本的同精度倍率。
