# 发布产物归档约定

本目录仅将当前发布文件放在 `latest/` 并允许纳入版本管理；历史版本保留在本地忽略目录，不删除。构建工程仍在 `tmp/`。当前交付为[ECG smoke / JTAG](latest/README.md)，运行依据见[板上证据](../docs/records/smoke_board_validation_20261017.md)，替换和归档核查见[发布更新记录](../docs/records/smoke_release_20261017.md)。

## 目录与内容

目录使用以下结构，版本标识写入 latest 的说明与清单；每个发布版本至少保留：

```text
releases/
  README.md
  latest/                    当前发布，指定交付文件放行
  history/<版本>/            历史副本，本地忽略、不删除
```

- `README.md`：用途、板卡/修订版本、工具版本、构建来源、程序行为、烧录步骤和限制；实际验证记录链接docs/records/。
- `artifacts.json`：每个交付文件的相对路径、字节数、SHA256，以及源码/构建来源和验收记录位置。
- 与启动方式匹配的实际交付文件；当前是hardware中的bit/XSA/PS初始化和prebuilt中的smoke ELF，没有BOOT.BIN。
- 烧录所需的匹配初始化文件，例如 QSPI 的 `fsbl.elf`；其他启动方式按需要确定。
- 验证文档链接：实际板上输出、校验结果及未验证项统一存docs/records/，发布清单引用其路径。

根据交付需要额外保留匹配的 `.bit`、`.xsa` 和应用 `.elf`。如保存 BIF，使用归档目录内有效的相对路径并核查引用；不要原样复制仍指向旧工作区的 BIF 或启动配置。

完整 Vivado/Vitis 工作区、`.runs`、`.gen`、缓存、波形、逐行日志和重复备份继续放 `tmp/`；发布目录保留必要证据摘要。正式源码和可复现脚本在 `src/rtl/`、`build/` 等目录，发布文件不能替代源码。

## 归档时机与检查

1. 明确验收目标：JTAG 运行、QSPI 复位启动、完整断电启动及 ECG 功能是不同阶段，交付说明逐项标明。
2. 用户确认交付当前版本后，使用对应产物及实际证据归档；完整掉电自启动需另外断电上电、不点击 Run 观察，未做则不能标为通过。
3. 首次建立 latest；后续更新前，将旧 latest 可恢复归档到 `history/<旧版本>/`，检查源/目标范围和冲突，再创建新 latest。不移动活动工程，不覆盖历史版本。
4. 对照原产物核对 SHA256，并检查路径、说明和验收证据。
5. 保留原工作区；后续清理另行授权，不因归档自动删除 `tmp/`。

历史版本不覆盖。latest 随当前交付更新，旧文件先归档，不删除；其他旧版本目录同样本地忽略。无法确认板卡修订、源码或某项实测时如实记录，不能把不同机器、不同镜像的验证合并成一次成功。

## 本地保存与团队共享

`releases/` 是本地项目目录，不会被 Windows 自动清理；仍需正常备份。`.gitignore` 默认忽略其他发布路径，只放行本说明及latest明确的smoke源码/脚本、清单、bit/XSA/初始化文件和ELF；工作区及运行日志不放行。旧Hello World/QSPI在本机`history/20261013-hello-world-qspi-v1/`，原字节保留且历史目录忽略；即使latest被放行，也不代表已经暂存、提交或推送。

旧文件如果已经被 Git 跟踪，增加忽略规则不会取消跟踪；需按会话授权另行操作索引，不删除本地文件。远端发布、上传、提交和推送需要另外授权。
